# Junos traps

Seen on a QFX5100-48S-6Q running Junos 21.4R3.

- Changes stage in a candidate and apply at `commit`. `commit confirmed N` applies them and rolls them back after N minutes unless another `commit` confirms them. `commit` also saves: there is no separate save.
- `load set terminal` reports a refused statement as `terminal:12:(8) syntax error: ...`, then says `load complete` and keeps every statement it accepted. Circuit discards the whole candidate on any refusal.
- A value is cut at `(`, `&`, or `|` unless it is quoted: `description a|b` is stored as `a`, with an error. The render quotes every value that is not a plain word.
- The device decides for itself which values it prints in quotes: `noc@example.com` comes back quoted, `"Router"` comes back plain. The plan compares values without their quotes.
- The device prints only the longest form of a statement. `set protocols rstp interface xe-0/0/0` disappears once `... xe-0/0/0 edge` is set, so the render leaves it out too.
- A delete cannot stop at a list whose entries are named: `delete interfaces xe-0/0/1 unit` is refused with `syntax error, expecting <identifier>`, while `unit 0` works. `show` refuses the same way. A list of plain values, such as `vlan members` or `ciphers`, can go whole.
- `delete` with a value removes the statement only when the value matches. Otherwise it says `warning: statement not found` and changes nothing.
- A `?` shows help and is not executed, but the Enter after it sends the line typed so far, which may be a complete command.
- `operator`, `daemon`, `bind`, `kmem`, `nobody`, `sshd`, `tty`, and `uucp` are system accounts. A user with one of those names fails the commit check: `user name is used by a system account`.
- Root logs in to a shell, `root@:RE:0%`, and reaches the CLI with `cli`. Every other user lands in the CLI.
- A password set with `plain-text-password-value` prints as a `$6$` hash. SNMPv3 passwords print as `$9$` keys, which can be turned back into the password. The read redacts both.
- An SNMP community prints in clear, and its value is also its name, so a new value is a second community. Circuit deletes the old communities by name, looked up during the apply and never printed, then sends the new one. A version 2c trap group is named by the community its traps carry, and is handled the same way.
- A version 3 trap receiver's port is `snmp v3 target-address <name> port`; `address-port` is a syntax error. `system syslog host <host> transport tls` passes `commit check` with no CA at all (21.4R3-S8.5).
- A firewall filter name is unique across families, so the services filter is `circuit-services` for IPv4 and `circuit-services-v6` for IPv6.
- A VLAN interface's MTU higher than what its ports carry commits with only a warning: `mtu 9000 is bigger than member link`.
- There is no `protocols stp`. Plain STP is RSTP limited with `force-version stp`.
- sFlow interfaces print with their unit, `xe-0/0/0.0`.
- The factory VLAN `default` can be deleted.
- BGP without a license commits with only a warning, `requires 'bgp' license`, and sessions establish. The same is true for the other licensed features.
- Junos accepts and announces every route over eBGP unless a policy says otherwise: `Default eBGP mode: advertise - accept, receive - accept`. A session without a policy is given `circuit-reject-all`.
- An export policy sees every active route, not only BGP's. Every export starts with `circuit-bgp-origin`, which passes on BGP's routes, the prefixes in `routing.bgp.originated_prefixes`, and the aggregates, and rejects the rest.
- `routing-options confederation` exists only for the whole router: under a routing instance it is `syntax error: confederation`. It prints as `confederation <identifier>` and one `confederation members <AS>` line per member. Junos's documentation lists every member AS, its own too, and so does the render. `show bgp neighbor` shows a neighbor in another member AS with the option `Confed` and `Local: AS <member AS>`, and an external one with `Local: AS <identifier>`.
- An aggregate counts every more specific active route, direct routes too. `circuit-aggregate-contributors` keeps BGP's routes and the originated prefixes. There is no summary-only: `circuit-bgp-origin` rejects the routes inside an aggregate with `summary_only`.
- No setting sends one neighbor a default route. Circuit adds `aggregate route 0.0.0.0/0 passive preference 4294967295`, which is always there and loses to any other default route, so forwarding stays as it was. The session's export starts with `circuit-default-route`, which announces the active default route. A static default through the neighbor itself went out with the neighbor's own address as next hop, so the term sets `next-hop self`.
- A policy's or a filter's terms are kept in order, and `set` adds a new term at the end. A change to one rewrites it whole.
- One policy term cannot filter IPv4 and IPv6 prefixes together: `invalid prefix ::/0 for family inet`. A rule for both families becomes a term for each, and so do the prefixes a policy of Circuit's own lists, such as `networks` and `networks-v6`.
- A port filter cannot match the VLAN a frame is switched in: `learn-vlan-id not supported on ingress interface`.
- IPv4 routes over an IPv6 session need a local IPv4 address under the family: `Local IPv4 address must be configured`.
- A DHCP server and a DHCP relay cannot share an interface: `Interface irb.10 already configured`.
- A port's MTU counts the Ethernet header. `mtu 9018` carries 9000-byte packets with a VLAN tag, and a VLAN interface's 9000 then commits without a warning.
- The serial console has no flow control. Statements pasted into `load set terminal` at once overrun it: some arrive garbled and the load reports syntax errors. The `^D` that ends the load can be lost, leaving the console in it. Circuit sends each statement after the echo of the one before.
- After a login the console prints `Last login: ...`, which ends in `login: ` like the login prompt. Only a `login: ` on a line of its own is the prompt.
- A factory-default switch runs Auto Image Upgrade, which prints on the console every few seconds until `delete chassis auto-image-upgrade` is committed.
- `show lldp neighbors` has no column for the far port: its `Port info` is the far port's description. `show lldp neighbors detail | display xml` has the port in `lldp-remote-port-id`, and Circuit reads that. There `lldp-local-port-id` is a number, `520`; the port's name is in `lldp-local-interface`.
- BFD on a BGP group, an OSPF interface, and a static route takes `bfd-liveness-detection minimum-interval N` and `multiplier N`. It prints both as sent, even the default `multiplier 3`. A multihop group takes it without a `local-address`.
- BFD on a BGP session starts only once the session is up: `show bfd session` lists nothing for a session in `Connect`, though the session shows `<BfdEnabled>`.
- A static route with BFD is withdrawn while its next hop does not answer BFD, so `show route` shows nothing for it. A session that is down sends every 2 seconds, `Transmit Interval 2.000`, whatever the interval.
- `bfd-liveness-detection` on a static route also watches a `qualified-next-hop`: a session to that address starts.
- `set switch-options interface xe-0/0/1 interface-mac-limit 1 packet-action drop` is stored on the logical interface, in two statements: `... interface xe-0/0/1.0 interface-mac-limit 1` and `... interface-mac-limit packet-action drop`. The render writes those two.
- An `ethernet-switching` filter takes `from ether-type ipv4`, `ipv6`, and `arp` by name. Ethertypes and an `ingress_acl` would both be the port's `filter input`, so Circuit refuses the two on one port rather than merge them.
- An `ethernet-switching` filter matches an IPv4 source as `from ip-source-address`, but an IPv6 one only under `from ip-version ipv6 ip6-source-address`; `from ip6-source-address` is a syntax error. A MAC address prints back with its length, `02:00:00:00:00:01/48`. A port bound to its hosts gets one filter, `circuit-bound-xe-0-0-1`, written in that form.
- An `ethernet-switching` filter has no match on what an ARP packet says, only `arp-type` request or reply. A bound port takes ARP from its hosts' MAC addresses, but cannot stop one of them claiming a neighbor's address in it.
- A filter on a port with no optic in it commits, but `show pfe filter hw filter-name <filter>` says `No hardware instance present` until the port exists. On a port in use it says `Programmed: YES`.
- A bound port drops what doesn't match at once. With a wrong address bound, the host's pings go unanswered. With a wrong MAC bound, its ARP is dropped too, so the gateway answers `Destination host unreachable`.
- LLDP sends a port's SNMP index as its port ID, `PortIdSubtype: local`, `PortId: 520`, so a neighbor cannot tell which port it is. `set protocols lldp port-id-subtype interface-name` makes it send `et-0/0/52`, and the render sets it wherever LLDP runs.
- `rpf-check mode loose` under `family inet` or `inet6` commits without a warning. Yet Juniper's Feature Explorer lists loose mode for the QFX5120 and later only. A QFX5100 on Junos 16.1 was reported to check in loose mode as in strict ([juniper-nsp, March 2017](https://puck.nether.net/pipermail/juniper-nsp/2017-March/033968.html)). Circuit refuses loose. With `rpf-check`, `show interfaces irb.<unit> extensive` lists `uRPF` in the family's flags and counts `RPF Failures`.
- Graceful restart is on only with `routing-options graceful-restart`, for every BGP group at once: `show bgp neighbor` then lists `GracefulRestart` in its options. `graceful-restart` on a group, or under `protocols bgp`, turns nothing on alone. Without any of them, BGP still helps a neighbor that restarts: a group's `graceful-restart disable` adds `GracefulRestartHelperDisabled`. So Circuit refuses graceful restart on only some neighbors.
- Two `as-path` names in one term match a route when either matches. `as-path-neighbors`, `as-path-origins`, and `as-path-transits`, each with an `as-list`, join `as-path` by AND, and `as-path-transits` matches the first and the last AS too. An `as-list` refuses AS 0, `RPD Policy: Invalid AS 0`, and AS 4294967295, `Restricted AS value (4294967295) not permitted`. An AS path regular expression takes both, and an alternation with ranges, `(23456|64496-64511)`, but a set of several, `[23456 64496-64511]`, fails the commit check: `invalid character class`. Checked with `test policy` against static routes with `as-path path` and `community`.
- `display set` prints `authentication-order` and `accounting events` one value a line, in their order. `delete system tacplus-server` takes every server at once. `accounting destination tacplus` without a TACACS+ server fails the commit check. With `authentication-order [ password tacplus ]` and the servers unreachable, a local user still logs in (21.4R3-S8.5).
- An OSPF MD5 key is 16 characters at most. A longer one fails `commit check` with `ospf authentication-key "<the key>"(24) longer than 16 characters`, the key in clear. The switch prints the key as `$9$...`, and `stub` or `nssa` only through what it holds, such as `nssa default-lsa default-metric 15`.
- A VLAN with a `vlan-id` takes no unit with `vlan-id-list` or `input-vlan-map`: `interface with vlan-id-list/inner-list cannot be added to a vlan with a vlan-id/vlan-tags configured`, and no unit 0 trunk joins a VLAN without one. So a QinQ VLAN has no ID, and each trunk joins it with `unit <id> encapsulation vlan-bridge` and `vlan-id <id>`, beside its unit 0 under `encapsulation flexible-ethernet-services` (21.4R3-S8.5).
- `vlan-rewrite translate <from> <to>` on a trunk's unit 0 needs the VLAN of ID `to` among its `vlan members`, or `commit check` fails. It fails too when `from` is the ID of a member VLAN, and when two translations share a `to`: `Ambiguous to-vlan-id statement present`. Beside `native-vlan-id`, it passes with `native-vlan configured shouldn't have VLAN translation configured under trunk`. A second `translate` of one `from` replaces the first (QFX5100, 21.4R3-S8.5, in a candidate).
- RA guard takes `router-advertisement-guard vlans <name>` alone: `stateless` and `stateful` after it are syntax errors. A port is `interface <unit> mark-interface block` or `trusted`. In DHCP snooping, `group <name> overrides trusted` or `untrusted` commits without a warning (21.4R3-S8.5).
- `display set` prints a router advertisement's prefix alone only when it has no option, such as `no-autonomous`, and prints the DNS servers before the prefixes. On an IRB unit whose VLAN has no port up, `show ipv6 router-advertisement interface` says `Router advertisement not running` (21.4R3-S8.5).
- An address-assignment pool holds one family: `family inet` set on a pool with `family inet6` replaces it. An inet6 `range` takes `low` and `high` with their length, `2001:db8::1000/128`; without it, `missing required prefix length`. `dhcp-local-server dhcpv6` commits on a QFX5100, with `delegated-pool` and `process-inform pool` under a group's `overrides`. `display set` prints a pool's `maximum-lease-time` before its DNS servers (21.4R3).
- Right after a commit, a new SSH login can be reset with `ECONNRESET` for some seconds. It reset Circuit's proof login after commits that deleted a DHCPv6 group, its pools, and a router advertisement interface. Some deleted an IRB unit and its VLAN too. It also reset the first login of an apply 5 seconds after a commit that added them. A login 10 to 20 seconds later passed (QFX5100, 21.4R3).
- IS-IS commits and runs on a QFX5100 without its license, with `warning: requires 'isis' license`. The switch takes its NET from `lo0.0`'s `family iso address`. `show isis interface` lists `lo0.0` as passive with or without `passive` (21.4R3-S8.5).
- With `protocols isis topologies ipv6-unicast`, an interface's IPv6 metric is `level <n> ipv6-unicast-metric`, apart from its `metric`, so Circuit writes both from the one metric. `commit check` passes `topologies ipv6-unicast` beside `no-ipv6-routing` without a word, so `circuit validate` refuses `multi_topology` without IPv6 (QFX5100, 21.4R3-S8.5, in a candidate).
- A BGP group in a `virtual-router` routing instance takes the main instance's AS. Its router ID is the address of one of the instance's own interfaces, unless the instance sets `routing-options router-id`. The instance's own `routing-options graceful-restart` turns graceful restart on for its groups (21.4R3-S8.5).
- `routing-options instance-import` takes routes from other routing instances by a policy whose terms match `from instance <name>`, or `master` for the main one. `from policy <name>` runs another policy as a subroutine there. A QFX5100 commits both without a license warning (21.4R3-S8.5).
- `system services ssh` takes no `routing-instance`: a syntax error. `system name-server <address> routing-instance <instance>` fails `commit check` with `Only routing-instance supported is mgmt_junos`. A syslog host, an NTP server, a RADIUS or TACACS+ server, and a trap group in a routing instance pass it. So do a DHCP local server and its address pool under `routing-instances <instance>` (21.4R3-S8.5).
- A policer's `bandwidth-limit` and `burst-size-limit`, and a port's `shaping-rate`, print with `k`, `m`, or `g` only when that leaves a whole number below 1000. `250000` prints as `250k`, `2000000` as `2m`, and `1500m` as `1500000000`, while `1250000` stays. A port's `shaping-rate` takes no `burst-size`: `syntax error`. A two-color policer in a filter of the switching family passed `commit check` (QFX5100, 21.4R3, in a candidate).
- MPLS and LDP pass `commit check` on a QFX5100 without their licenses, with `warning: requires 'mpls' license` and `warning: requires 'ldp' license`, on a port's unit and on an IRB unit. Nothing was committed, so whether LDP runs without them is not known (21.4R3-S8.5).
- Without BGP configured, `show bgp neighbor` and `show bgp summary` say `BGP is not running`. With `| display json` that is the `data` of an `output` element, and the text form's `Warning: License key missing; requires 'bgp' license` is left out (21.4R3-S8.5).
