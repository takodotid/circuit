# FortiOS traps

Seen on a FortiGate 3700D running FortiOS 6.2.2, without a license.

- A change applies at `next` or `end`. With `cfg-save automatic`, the factory setting, it is saved at once. `abort` discards the changes to the one object being edited, and leaves its table too. Inside a table it is `Unknown action 0`, and entries already left with `next` stay applied.
- `cfg-save revert` keeps changes running but unsaved. `cfg-revert-timeout` seconds after a change, the device announces `System will reload` and reloads its saved configuration. This restarts the configuration, not the hardware, and takes about two minutes. `execute cfg reload` does it at once, without asking, and says `no config to be reloaded` when nothing is unsaved. `execute cfg save` saves, and so does setting `cfg-save automatic` again.
- `cfg-save revert` set while saving is automatic is saved itself. After a reload the device stays in revert mode. Every later change by hand is then undone after the timeout, until someone saves or sets `cfg-save automatic`. Circuit sets it back at the end of every apply.
- Circuit does not use `execute config-transaction start N` on 6.2.2: a candidate that `commit` applies and `abort` discards. Inside one, and only there:
    - Deleting an entry does not release what its lists point to. Deleting a policy, then the address it used, is refused: `The entry is used by other 1 entries`.
    - A transaction whose session is cut off keeps every object it touched locked for N minutes: `Can not config the object since it's being configured by another transaction`.
    - Editing a `firewall policy6` entry after `unset central-nat` ends the session at `edit`.
    - Deleting the user you are logged in as ends the session with `cmdb_txn_cache_data ... failed`. Every later transaction then fails until the device restarts.
    - `show` prints a new static route or policy with the comment of the last new one. The commit corrects it.
    - OSPF's `config redistribute` is refused: `config child object 'redistribute' is not handled in transaction`.
    - A certificate added in one cannot be used by name until the commit.
- The CLI pages long output with `--More--`. Once answered, it erases the prompt with spaces and a carriage return.
- A `?` typed anywhere shows help at once and is never sent. Ctrl-V before it types it literally.
- The idle timeout, `admintimeout`, is 5 minutes by default; the session then returns to `login:`.
- With `pre-login-banner` on, the console shows the banner and waits on `(Press 'a' to accept):` before `login:`. Circuit answers `a`.
- `grep` after a pipe takes no `-E`. A command ending in `| grep` prints its matches, then `Command fail. Return code -27`.
- `show` prints only settings that differ from their default, in its own order, not the order they were set. A new aggregate gets `device-identification enable` and `lldp-transmission enable` unasked. A new VLAN interface gets `device-identification enable` and `role lan`. Circuit unsets them.
- A port joins an aggregate only while nothing points to it, such as a static route: otherwise `entry not found in datasource`. A port in an aggregate cannot change speed, not even back to `auto`: `Interface speed cannot be set for aggregated interfaces`. So Circuit deletes what points to a joining port and creates it again after. A port whose speed changes leaves its aggregate and joins again. An aggregate that goes, or is left with no port, goes first, with what points to it.
- `unset secondary-IP` hides the list of secondary addresses and drops it. NTP's `unset type` hides its servers but keeps them: `set type custom` brings them back. NTP refuses to delete its last server while `ntpsync` is on. It refuses to empty the interfaces it serves on while `server-mode` is on: `There aren't any interfaces with NTP server enabled`. `unset server-mode` hides that list and lets go of its interfaces. The plan deletes a nested list before the setting that hides it, except `ntpsync`, which goes first.
- A DHCP server prints `dns-server1` only while `dns-service` is `specify`, the default, which `show` does not print. The factory server on `mgmt1` uses `default`, so the render writes `specify` before its resolvers.
- A DHCP relay adds Option 82 unless told not to: with `dhcp-relay-service enable`, an interface has `dhcp-relay-agent-option enable`, which only `show full-configuration` prints. `show` prints it once it is `disable`, and `unset` turns it on again. So the render writes `disable` unless the config asks for Option 82. `unset dhcp-relay-service` hides `dhcp-relay-ip` and the option but keeps them, and `set dhcp-relay-service enable` brings both back. While the relay is off, unsetting either is `command parse error`, so the plan unsets both first. A loopback has no relay: `set dhcp-relay-service` on one is `command parse error` (6.2.2).
- The timezone is a number of the platform's own, such as `53` for Jakarta, Bangkok, and Hanoi. The default is `00`, Eniwetok, at UTC+12; UTC is `80`.
- Global `alias` is set again at every start, whatever was saved.
- `log memory setting` prints its `status` whether on or off, and `unset status` turns memory logging on.
- Two interfaces that are up cannot have overlapping subnets: `Subnets overlap between ...`, in different VRFs of one VDOM too. An address that moves leaves the first interface before it joins the second.
- A static route identical to another is refused, even for a moment: `Duplicated entry`. Editing route 1 into what route 2 holds fails before route 2 changes. So a plan deletes every route that changes or goes before it creates any. Neither family prints a default route's destination.
- A deny policy gets `logtraffic disable`, and its action is not printed, since deny is the default. `send-deny-packet` exists only while a policy denies, and is `command parse error` otherwise. So the render writes `action deny` before it. A plan unsets it before `action accept` and sets it after `action deny`.
- `show` prints `unset` in two places: an ICMP service's `unset icmptype`, and a prefix list rule's `unset ge` and `unset le` for a bound it does not have.
- An SNMPv3 user authenticates with MD5 or SHA1 only. Only a community has hosts, not a user. Circuit decides who reaches every service with local-in policies instead.
- Under `log syslogd setting`, `set mode reliable` and `set enc-algorithm high` each set the port back to their own default, 514 and 6514, saying `Port changed to default (6514)`. So the render sets the port after them. `show` prints `port 6514` although it is the default with TLS. A collector that cannot be reached counts as `failed` in `diagnose test application miglogd 6`.
- NetFlow's `active-flow-timeout` is in minutes, 1 to 60, and `inactive-flow-timeout` in seconds, 10 to 600.
- The console ignores a user's trusted hosts.
- A tunnel's interface takes an IPv4 address only as a host, with the far end in `remote-ip`. `set ip 10.0.0.1 255.255.255.252` on one is dropped without a word.
- A GRE or VXLAN tunnel creates an interface of its own, named after it, which goes when the tunnel goes. VXLAN has no local address: it leaves from the address of the interface it points to.
- An IPsec phase 1 makes its tunnel's interface too, and `show` prints a new one with `peertype any` and `net-device disable`, which Circuit writes. It leaves out `keylife 86400`, and a phase 2's `keylifeseconds 43200`. A phase 2 hides `dhgrp` while `pfs` is `disable`. The tunnel's interface takes no MTU: `set mtu-override` and `set mtu` are `command parse error`. In multi-VDOM mode the phase 1 belongs to a VDOM and its interface is global. All of it seen on 6.2.2.
- A phase 1 with `authmethod signature` and `peertype peer` doesn't print `peertype`, so the plan counts `peer` as its default. `set peer` takes an entry of `user peer`, and that entry's `ca` a `vpn certificate ca`: `entry not found in datasource` otherwise. A phase 1's `dpd` is `on-demand`, `dpd-retryinterval` 20, and `dpd-retrycount` 3 when nothing says, none printed. The interval takes 0 to 3600 seconds, the count 0 to 10, and `dpd disable` hides both. Going from a key to a certificate and back, and removing a tunnel with its CA and certificate, took the plan's order. All of it seen on 6.2.2.
- A phase 1's NAT keepalive interval, `keepalive`, takes 10 to 900 seconds, and is 10 when nothing says, which `show` doesn't print. It exists only while `nattraversal` is `enable`, the default: with `forced` or `disable`, `set keepalive` is `command parse error`, and the old value comes back with `enable` (6.2.2).
- A phase 2 carries one family. With `src-addr-type subnet6` and `dst-addr-type subnet6` it carries IPv6, `::/0` both ways, which `show` doesn't print, also under a phase 1 with IPv4 ends. The tunnel's interface takes an IPv6 address under `config ipv6`, but has no IPv6 peer (6.2.2).
- A policy-based tunnel's `vpn ipsec phase1` takes no `ip-version`, `local-gw6`, or `remote-gw6`, its `vpn ipsec phase2` no `subnet6`, and `firewall policy6` no `action ipsec`: `command parse error`. `firewall policy` takes `action ipsec` only with named interfaces: with `srcintf "any"` it is `command parse error before 'ipsec'`, and with `dstintf "any"` the `vpntunnel` check fails. A new phase 1 prints `peertype any`, and one with `authmethod signature` and `peertype peer` doesn't print `peertype`. A policy is `inbound disable` and `outbound enable` unless set. A phase 1's or phase 2's name holds 35 characters. Traffic the device sends from an address in a selector goes into the tunnel too (6.2.2).
- A route-based tunnel's interface takes `set vrf` as any interface does. Its network and routes go to that VRF, and IKE and ESP leave from the interface that holds `local-gw`, in its own VRF. `unset vrf` moves it back to VRF 0 in place, and the tunnel stays up (6.2.2).
- A tunnel negotiates only once a firewall policy accepts traffic through its interface; a deny policy doesn't count. Until then `diagnose debug application ike -1` shows `ignoring request to establish IPsec SA, no policy configured`. Two tunnels between two addresses of one VDOM never come up: the IKE daemon mixes up their messages, `invalid IKE request SPI` (6.2.2).
- In multi-VDOM mode `diagnose debug` is `Unknown action 0` at the top prompt. Under `config global` it works, and its output comes to that session, from every VDOM (6.2.2).
- `user peer` matches a peer's certificate by `subject` or `cn` (with `cn-type`), never by its subject alternative names. Out of the box, `vpn certificate setting` has `subject-match substring` and `cn-match substring`, which Fortinet documents as a match on any part (6.2.2).
- `vpn certificate setting` belongs to each VDOM: under `config global` it is `command parse error`. `subject-match value` set in one VDOM left root's and mgmt's at `substring`, and `show` prints the section empty at its defaults. Fortinet documents `value` as an exact match of an attribute's value, with a subject of several attributes as its example. No IKE peer tried it here (6.2.2).
- A static route has no VRF of its own. It lands in the VRF of the interface it leaves through, as `get router info routing-table all` shows, so a blackhole route cannot go in a VRF.
- BGP has no VRF setting, and one table, VRF 0's: `get router info bgp network <prefix>` names it `Default-IP-Routing-Table`. A session to a neighbor behind an interface in VRF 1 came up, with `set interface` or without, but its routes went to VRF 0, `inactive` there. A `config network` prefix of VRF 1 was `% Network not in table`, and one of VRF 0 went to the neighbor in VRF 1 (6.2.2). Fortinet's 6.4.0 New Features guide adds BGP in a VRF.
- OSPF has no VRF setting: each interface runs it in the VRF it routes in, one process for each VRF, `OSPF process 1, VRF 1` in `get router info ospf neighbor`. The routes it learns go to that VRF, and `redistribute "connected"` and `"static"` take only that VRF's routes. BFD came up on a link in the VRF. An interface that leaves the VRF takes its adjacency to VRF 0 in place. OSPFv3 runs in VRF 0 only: it doesn't run on an interface in another VRF, which `get router info6 ospf interface` leaves out (6.2.2).
- BFD's timers under `config system settings`, `bfd-desired-min-tx`, `bfd-required-min-rx`, and `bfd-detect-mult`, exist only while `bfd` is on there. `get` hides them otherwise. Their defaults, 250, 250, and 3, are not printed. So the render sets `bfd` before them, and a plan unsets them before `bfd`.
- A static route takes `set bfd enable`, IPv4 and IPv6, in a VRF too. The route stays in the table while its BFD session has never come up.
- BGP asks for a BFD session only once its session is up: `get router info bfd requests` lists nothing for a neighbor still `Active`, with `ebgp-enforce-multihop` or without.
- On a multihop BGP session BFD runs single-hop. It sends to UDP port 3784 and ignores the multihop BFD the peer sends to port 4784. Against a CCR2216 on RouterOS 7.23.5, `get router info bfd neighbor` stayed `DOWN` with remote discriminator `0`, and BGP flapped. `config router bfd` holds only single-hop neighbors. Circuit refuses BFD on a multihop session.
- The stateless ACL, `firewall acl` and `acl6`, only drops: it has no action.
- A route map stops at the first rule that matches, with no way to go on to the next. Its rules permit unless told to deny.
- `show vpn certificate local` prints a certificate without its text or key. `show full-configuration` prints both, the key encrypted.
- A private key the device cannot read gets `Invalid private key, password may be required`, with no `Command fail`, and the session goes on. A key whose lines end in CR LF gets the same answer, because the CLI takes each CR as a line. The certificate fails only at `end`: `Attribute 'private-key' MUST be set`.
- A GRE or VXLAN interface takes no flow sampler, and says so without `Command fail`: `Netflow sampler isn't supported on Tunnel interface..`, and the same for sFlow and for VXLAN.
- A port in an aggregate has no `icmp-send-redirect` (`command parse error`), and loses it when it joins one.
- `purge` empties a table after asking `(y/n)`.
- A VLAN interface has no LLDP settings: `set lldp-transmission` on one is `command parse error`. An aggregate's LLDP sends and receives on each of its ports.
- `diagnose lldprx neighbor summary` shows the FortiGate's own port as an index, `port 23` for `port5`. `diagnose lldprx neighbor details` gives the port's name in `port.txt`, and Circuit reads that. Both print nothing when no neighbor was received.
- A loopback has no MTU of its own and runs no VRRP. An interface's name has at most 15 characters.
- Multi-VDOM mode (`config system global`, `set vdom-mode multi-vdom`, `end`) asks `Do you want to continue? (y/n)` and logs every session out. Traffic keeps flowing: everything stays in `root`. From then on `system interface` lists `npu0_vlink0` to `npu3_vlink1`, two links between VDOMs for each NP6 chip, which cannot be deleted. Certificates (`vpn certificate local` and `ca`) and `log disk setting` belong to each VDOM, and are `command parse error` under `config global`. The system settings, interfaces, DNS, NTP, SNMP, syslog, sFlow, NetFlow, and session helpers are global, and are `command parse error` inside a VDOM.
- An interface moves into another VDOM (`config global`, `config system interface`, `set vdom`) only once nothing in its VDOM points to it, such as a static route. A session that came in on it stops answering once it moves, so move it from a session on another interface.
- `capability-default-originate` sends a default route of the device's own, even through a `route-map-out` that denies everything.
- An `aggregate-address` goes through `route-map-out`: a denied one is withdrawn. It is announced while the BGP table holds a route inside it, which `summary-only` marks `s` and keeps from the neighbors. The device routes the aggregate to Null, at distance 200. `get router info bgp neighbors <address> advertised-routes` leaves the aggregate out although the neighbor gets it; `get router info bgp network <prefix>` lists whom it went to.
- There is no WireGuard: `command parse error`. A route map has no large community, and SNMPv3 no SHA256.
- BGP has no RPKI: a neighbor's `set rpki` is `command parse error`, and `show full-configuration router bgp` lists no route origin validation (6.2.2). Fortinet's 8.0 CLI reference adds `route-origin-as-validation` and `config rpki-server`.
- A BGP neighbor's `maximum-prefix` has no restart: `set maximum-prefix-restart` is `command parse error`. Its `restart-time` is graceful restart's, as Fortinet's 6.2 CLI reference says (6.2.2). Fortinet's CLI references up to 7.6 have no restart either.
- A BGP neighbor has no TTL security (RFC 5082): `set ttl-security-hops` is `command parse error`. It has `ebgp-enforce-multihop`, and `ebgp-multihop-ttl` for the TTL it sends, but nothing that checks the TTL of what arrives (6.2.2). Fortinet's CLI references up to 7.6 have nothing more.
- A BGP neighbor has no role (RFC 9234): `set role` is `command parse error`, and `show full-configuration router bgp` lists none for a neighbor (6.2.2). Fortinet's CLI references up to 7.6 have none either: their `role` is a VRF's, for VPNs.
- There is no EVPN: `config system evpn` is `command parse error` in a VDOM, and so are `set evpn-id` on a VXLAN and a BGP neighbor's `set activate-evpn` and `set activate-vpnv4` (6.2.2). Fortinet's 7.4.0 New Features guide adds EVPN over VXLAN, in VRF 0 only. Fortinet's CLI references up to 7.6 have no MPLS.
- A VDOM's short name is 11 characters at most: `The maximum length of the vdom short name is 11.`
- `confederation-peers` takes the other member ASes as quoted words. `get router info bgp neighbors` then gives a neighbor in one of them the router's `as` as its local AS, with `Neighbor under common administration`, and any other eBGP neighbor the `confederation-identifier`.
- A BGP neighbor has `route-reflector-client` and `route-reflector-client6` only while it is internal. While the router's `as` is unset, or `remote-as` is another AS, setting them is `command parse error`. The render writes both ASes before them.
- A FortiGate checks the source of what arrives out of the box: each interface has `src-check enable`, and each VDOM's `system settings` has `strict-src-check disable`, which checks feasible paths. Neither has an IPv6 setting of its own.
- `execute backup config flash <comment>` keeps a revision on the device, and `execute restore config flash <id>` restores one.
- The factory dedicates `mgmt1` and `mgmt2` to management, at `192.168.1.99` and `192.168.2.99`.
- On the serial console a line ends at a carriage return. A session left open stays logged in, and one left inside `config` stays there, so the next login must first leave and log out. The console runs at 9600 bits per second: reading the sections Circuit manages takes about two minutes.
- A data port can stay `netdev status: down`, with `rx_carrier: 0` in `diagnose hardware deviceinfo nic`, while the far end reads `link-ok` and frames reach the port's switch chip. Fixing the speed does not help, in a LAG or out of one; a reboot does. `link_status: Up` there means nothing: a port with no cable shows it too.
- Transparent mode, `set opmode transparent` under `config system settings`, needs a `manageip`: `Attribute 'manageip' MUST be set`. A link-local one, such as `169.254.0.1/255.255.255.255`, is accepted. Switching takes every interface's address away, replaces the static routes with one default gateway, and puts every port in one bridge. It deletes the factory's custom services, `ALL` among them, so a policy that uses `ALL` is refused: `entry not found in datasource`. It also adds an empty static route in each family and turns memory logging on, so an apply that switches the mode plans once more after it.
- `forward-domain` exists only in transparent mode: in NAT mode it is `command parse error`. VLAN interfaces in the same forward domain are bridged, and each frame leaves with the tag of the interface it leaves by.
- Leaving transparent mode, `set opmode nat`, is refused with `IP address must be a class A, B, or C ip` unless an address is given with it.
- A VLAN interface holds its VLAN ID and parent alone. A new one on the same pair is refused: `vlanid and underlying interface must be a unique pair`. So a rename deletes the old one first, with the routes and policies that use it, and makes them again under the new name.
- `config system proxy-arp` takes one entry per address, `set interface` and `set ip`, and is printed empty when it has none.
- An AS path list takes any regular expression without a word, even one that does not compile, `_(6451[2-9]_`. A `regexp` holds 63 characters at most, and the name of an AS path list, a community list, or a route map 35. A route map's `set-aspath` gives a route the device originates no AS path, even with `set-aspath-action replace`, so only routes from a BGP neighbor test an AS path match. On routes from a RouterOS neighbor, `_` matched a space and the start and end of the path, and `{n}`, `{m,n}`, and `{0,0}` counted ASes. A community list with a `permit` rule for each value matches a route with any of them, and an expanded list matches `^64500:[0-9]+$`.
- After a route map, or a list it uses, changes, the device keeps what it decided on the routes it holds. A neighbor's routes were judged again only after `execute router clear bgp ip <neighbor> soft in`, and the routes sent to it only after `soft out`. Without it, a changed prefix list or route map still had no effect after 90 seconds, and an AS path list behaved the same. The soft clear prints nothing and keeps the session up: the device asks the neighbor to send its routes again (RFC 2918). A changed announcement leaves within the advertisement interval, 30 seconds. `ipv6` with an IPv4 neighbor's address judged its IPv4 routes again too. For a neighbor not established a soft clear prints nothing, and for an unknown one `%BGP: Unknown neighbor`. So a plan ends with a soft clear of each neighbor whose policy changes, in that direction.
- A user group may not have a TACACS+ server's name: `already used by tac_plus server`. A server's `source-ip` must be on an interface of its VDOM, or it is `not valid source ip`. In multi-VDOM mode the servers and the groups are a VDOM's, and an administrator's `remote-group` must be in the administrator's VDOM, or it is `not in admin user's vdom`. So the plan makes the wildcard administrator after the VDOMs' steps and deletes it before them. With it and the servers unreachable, the device's own administrators still log in.
- An OSPF border router announces a default route into a stub area, or with `stub-type no-summary` into an NSSA, as a type-3 LSA at `default-cost`, 10 unless set. Into an NSSA with summaries it announces none until `nssa-default-information-originate always`, then a type-7 LSA at `nssa-default-information-originate-metric`. `show` leaves both costs out at 10, but prints an interface's `hello-interval` and `dead-interval` once set, even at their defaults of 10 and 40 seconds.
- An OSPF area's `config range` has no cost: a border router announces the range at the largest cost inside it, as RFC 2328 says, and routes the range to Null (`is a summary, Null`). `show` leaves out `advertise enable`. A range took a prefix that another range held until a later line (6.2.2).
- OSPF's neighbors are the router's own `config neighbor`, each placed on the link whose network holds it. On a point-to-multipoint link one needs a cost: `Cost should not be empty for point to multipoint network.` `point-to-multipoint-non-broadcast` sends hellos to the neighbors alone, `point-to-multipoint` to 224.0.0.5. Both, and `non-broadcast`, say hello every 30 seconds and give up after 120 unless set. A loopback runs `Network Type LOOPBACK`, whatever `network-type` says. The default priority is 1 (6.2.2).
- An OSPF or OSPFv3 virtual link is an entry of the transit area's `config virtual-link`, with the far router's ID in `peer`. One of each version came up at once across one area. The OSPFv3 one leaves from an IPv6 address of the transit area, here a loopback's (6.2.2).
- `redistribute-l2-list` and `redistribute6-l2-list` under `router isis` take an access list, `router access-list` and `router access-list6`: a prefix list is `entry not found in datasource`. An access list's rule matches its prefix and what lies inside it unless `exact-match enable`, and `show` leaves out `action permit`. IS-IS takes neither a link between VDOMs (`type vdom-link`) nor a GRE tunnel's interface: `entry not found in datasource`. A VLAN interface takes no such link as its parent, and a software switch none as a member (6.2.2).
- `config system vdom-link`, under `config global`, makes two interfaces of its name and `0` or `1`, in root. Each moves to another VDOM with `set vdom` while nothing uses it. With `set type ethernet`, OSPF ran between two VDOMs across one (6.2.2).
- A router advertisement's DNS servers and search domains are set on each entry of `ip6-prefix-list`, as `rdnss` and `dnssl`: 6.2 has no other place for them. `show` prints `rdnss` with a space after the last address, and each domain of `dnssl` in quotes of its own. `ip6-max-interval` below `ip6-min-interval` is taken without a word. Their defaults are 600 and 198, and `ip6-default-life` 1800.
- A DHCPv6 server's `prefix-range` must lie inside its `subnet`, with a `prefix-length` at least the subnet's: `The DHCP6 server prefix ranges must be in the specified subnet`. A subnet wider than the interface's network, a /48 on an interface with a /64, is taken. A second server on an interface with an overlapping subnet is refused. `show` prints `lease-time` unless it is 604800, `prefix-range` before `ip-range`, and both before `dns-server1`. 6.2.2 holds four DNS servers, and has no setting for a server that gives no addresses.
- IS-IS has no passive interface: `set passive` under `isis-interface` is `command parse error`. A loopback's entry is `network-type loopback`, which `show` prints, and `point-to-point` or `broadcast` on it is a parse error. `show router isis` prints an entry's `status enable` and an empty `config redistribute` and `redistribute6` for each protocol, and leaves out `is-type level-1-2` and a metric of 10.
- IS-IS MD5 takes its key from a key chain only: with `auth-mode-l2 md5`, `set auth-password-l2` is `command parse error`, in `router isis` and in an `isis-interface` entry. Once the mode is unset, `unset auth-keychain-l2` is a parse error too, so the plan unsets the key chain first. A key chain's key needs `accept-lifetime` and `send-lifetime`, or `next` fails with `accept-lifetime must be set`. `show` prints its `key-string` in clear, which the read redacts, and its number as `edit "1"` (6.2.2).
- A policy route, `router policy`, sends what it matches to a `gateway` and an `output-device`. It has no table or VRF to send it to: `set vrf`, `set table`, and `set routing-table` are `command parse error`. A static route takes the VRF of the interface it leaves through, so there is no table beside the VRFs (6.2.2).
- `config router bgp` has no `config vrf-leak` on 6.2.2: `command parse error before 'vrf-leak'`. So routes cannot go from one VRF to another. Fortinet's 6.4.0 New Features guide adds it.
- IS-IS has no BFD: `set bfd` is `command parse error` in `router isis` and in an `isis-interface` entry. It has no topologies either (RFC 5120): `set multi-topology` and `set topology` are `command parse error`, and `get` under `router isis` lists no such setting (6.2.2). Fortinet's CLI references up to 7.6 have neither.
- `system ntp`, `system dns`, and `log syslogd setting` have no VRF setting: the device's own traffic leaves from the management VDOM, or from `root` (6.2.2).
- A shaping policy takes `any` for `srcintf` and `dstintf`, in either family. `show` prints the `bandwidth-unit` of a shaper unless it is `kbps`, the default, and no `per-policy` on a shared shaper. The factory ships five shapers. All but `shared-1M-pipe` print `per-policy enable` (6.2.2).
- In multi-VDOM mode `get router info bgp summary` at the top prompt is `command parse error`, and `sudo root get router info bgp summary` is `Unknown action 0`. It runs after `config vdom` and `edit root`. Without BGP there, it and `get router info6 bgp summary` print nothing (6.2.2).
- A `firewall ippool` of `type port-block-allocation` prints `block-size`, `num-blocks-per-user`, and `pba-timeout` only away from their defaults, 128, 8, and 30 seconds. So the plan counts the first two as their defaults, and the render writes no timeout of 30. `block-size` takes 64 to 4096, 100 too, `num-blocks-per-user` 1 to 128, and `pba-timeout` 3 to 300: `The pba-timeout value 2 must be in the range of 3-300.` There is no interim log of a block held: `set pba-interim-log` is `command parse error`. A pool's name may hold `/` (6.2.2).
- `firewall central-snat-map` takes and prints entries while the VDOM's `central-nat` is `disable` (6.2.2).
- `system nat64` belongs to each VDOM. Out of the box it is `status disable`, with RFC 6052's well-known prefix as `nat64-prefix` and `always-synthesize-aaaa-record enable`, and `show` prints it empty. `nat64-prefix` takes a /40, a /64, or an address with bits past its length without a word, though Fortinet's CLI reference says it must be a /96. Circuit writes a /96 only (6.2.2).
- A NAT64 policy, `firewall policy64`, takes an IPv6 address or group as `srcaddr` and an IPv4 one as `dstaddr`: the other family is `entry not found in datasource`. It takes `any` interfaces and a pool of any type, port block allocation too, while `system nat64` is off and while central NAT is on, which leaves its `ippool` and `poolname` in place. `show` prints `action accept`, and leaves out `logtraffic disable` (6.2.2).
- A new VDOM, `config vdom` then `edit <name>`, gets a tunnel interface `ssl.<name>` and a `system vdom-property` entry. Its `firewall address6` holds `all`, `none`, and `SSLVPN_TUNNEL_IPv6_ADDR1`. Deleting the VDOM, `delete <name>` under `config vdom`, took both away (6.2.2).
- A link monitor without `srcintf` is taken, with `this entry does not have source interface, automatically disable update-cascade-interface and update-static-route`. Its probes then follow the routing table, from the address of the interface they leave through, and a failure changes no route. A probe to any address of a loopback's network is answered by the device itself, so it is `alive`. `interval` is in milliseconds, 500 to 3600000, and a name is 35 characters at most. With `addr-mode ipv6`, `show` prints `protocol ping6`, and `source-ip6` after the rest. A change creates the link monitor again, with a new create time (6.2.2).
- `system pppoe-interface` belongs to each VDOM: under `config global` it is `command parse error`. An entry, at most 15 characters, takes `device`, `username`, `password`, `service-name`, and `ipv6`. It makes a global interface of its own name, `mode pppoe` and `type tunnel`, with `interface` its device, which goes when the entry goes. That interface has `defaultgw enable` at distance 5, but no MTU, no `dns-server-override`, and no flow sampler: `set mtu` and `set dns-server-override` are `command parse error`, and a sampler is `isn't supported on Tunnel interface`. Two entries can share a device, and `device` changes in place. An aggregate with no ports carries one. A port or aggregate takes `set mode pppoe` itself too, but its session then has no name of its own. 6.2.2 has no PPPoE server: `config system pppoe-server` is `command parse error`.
- A PPPoE interface has `config ipv6` only while its entry has `ipv6 enable`: `command parse error` otherwise. `unset ipv6` hides its IPv6 settings, `autoconf` and `dhcp6-prefix-delegation` among them, and `set ipv6 enable` brings them back as they were. So Circuit turns IPv6 off on the entry alone. With `dhcp6-prefix-delegation enable` it shows `dhcp6-prefix-hint ::/0` (6.2.2).
- An IPv4 static route takes a PPPoE interface as its `device`, with no gateway. An IPv6 one doesn't, with IPv6 on the session or without: `entry not found in datasource`. Policies of both families, local-in policies, and central SNAT take it. Deleting the entry while a route uses it is refused: `pppoe interface '<name>' is used.` (6.2.2).
- A dial-up phase 1, `type dynamic`, prints `dpd on-idle` and `dpd-retryinterval 60` unless set, which Circuit writes. It leaves out `assign-ip-from range`, `ipv4-netmask 255.255.255.255`, `dns-mode manual`, and `add-route enable`, its defaults. A client connected only once a firewall policy accepted traffic from the tunnel's interface: a policy with `srcintf "any"` did. Each client gets an instance of the tunnel, `<name>_0` and on, with a route to its address. The device narrowed a client that asked for all its traffic to the phase 2's `src-subnet` and the client's address. A client whose certificate another CA signed stayed `connecting`. Traffic from a client to the FortiGate's own address, a loopback's, was dropped: the tunnel's interface allows no ping (6.2.2).
- A FortiGate is a dial-up client with `mode-cfg enable` on a static phase 1: it takes an address from the pool, `assigned IPv4 address` in `diagnose vpn ike gateway list`. Its phase 2 then takes no `dst-subnet`, `command parse error`, and asks for all traffic (6.2.2).
- A user group may not have a RADIUS server's name: `ctest-rae is already used by radius server`. A RADIUS entry's `config accounting-server` takes an entry for each server, with `status enable`, `server`, `secret`, and `port`. The first `show user radius` after entering a VDOM left an accounting server's `set port` out, while later ones printed it, so Circuit refuses another accounting port (6.2.2).
- `diagnose sys session list` and `clear` work on the whole device in multi-VDOM mode, whichever VDOM the session is in: a list filtered by destination alone showed sessions of four VDOMs. `clear` without a filter cleared every session of the box, the tenants' and the SSH session's that ran it. Each CLI session starts without a filter, so set `diagnose sys session filter` first in the same session (6.2.2).
- `firewall traffic-class` takes class IDs 2 to 31, `The class-id value 1 must be in the range of 2-31.` A shaping profile's `default-class-id`, a shaping entry's `class-id`, and a shaping policy's `class-id` name an entry of it, or are `entry not found in datasource` (6.2.2).
- A shaping profile is `type policing` unless set, which drops what passes a class's rate. `type queuing` holds it in the class's queue, and only then do `limit`, `red-probability`, `min`, and `max` exist: a parse error otherwise. `limit` is the queue in packets, 5 to 10000, 1000 unless set, which `show` leaves out, and it is hidden while `red-probability` is not 0. A shaping entry's `priority` is `top`, `critical`, `high`, `medium`, or `low`, `high` unless set. The CLI takes a word's start for the word: `set max 50` set `maximum-bandwidth-percentage` while the profile was `policing` (6.2.2).
- A shaping profile refuses its shaping entries' guaranteed percents above 100 in all at each entry's `next`, `Sum of 'guaranteed-bandwidth-percentage' of all shaping-entries > 100%`, and discards that entry's change. So the plan changes the entries that lower theirs first (6.2.2).
- An egress shaping profile shapes only with the interface's `outbandwidth`, in kbit/s. The interface is global, and the profile belongs to its VDOM. Fortinet's 6.2.1 release notes list bug 469798: it doesn't shape offloaded traffic. A link between VDOMs, `type vdom-link`, is not offloaded (`no_ofld_reason: non-npu-intf`), and there a class capped at 10 or 20 kbit/s held 1000-byte pings to it, IPv4 and IPv6 (6.2.2).
- A shaping policy keeps `tos` only while `tos-mask` is not 0: a `tos` set before the mask is lost, and `show` prints `tos` first. `tos` is the whole byte, so a DSCP is `tos-mask 0xfc` with the DSCP times 4, `0xb8` for EF. It matches IPv6's traffic class the same way (6.2.2).
- A session takes the first shaping policy that matches its first packet, as `diagnose sys session list` shows with `shaping_policy_id` and `class_id`, and keeps it. Its class holds every packet of it, the replies too: a profile on the interface the replies left through shaped them by the request's class. `diffserv-forward` marks the packets that go the way of the first one, which arrived at the next VDOM with the new DSCP. The firewall's own pings, with `execute ping-options tos lowdelay`, matched no shaping policy and took the profile's `default-class-id` (6.2.2).
- `execute ping-options tos` takes `default`, `lowdelay`, `throughput`, `reliability`, or `lowcost`, and ignores a number without a word. `adaptive-ping enable` sends the next ping as the reply comes. `execute ping6-options` has no `adaptive-ping`, and its `interval` starts at 1 (6.2.2).
- A per-IP shaper polices: it drops what passes its rate, and `diagnose firewall shaper per-ip-shaper list` counts the drops. It counts each session, both ways, against the session's source address, `addr=` there (6.2.2).
- `diagnose netlink intf-class` and `intf-qdisc` are `command parse error` on 6.2.2.
- Between two VDOMs of one FortiGate, a route-based tunnel with certificates did not keep out what its `user peer` should have. `diagnose debug application ike -1` showed, as the tunnel answered: with `ca` and `subject "CN=ctest-b"` under `subject-match value`, or `subject "ctest-b"`, `certificate validation succeeded` for `CN=other-1` of the same CA. With `ca` alone, it succeeded for a certificate of a CA the VDOM doesn't hold. With `cn "ctest-b"` under `cn-match value`, it failed for `CN=other-1` and succeeded for the one of the other CA. A dial-up tunnel refused the one of the other CA. The other VDOM held each of those certificates as its own, which may be why. A test against another device is still to do (6.2.2).
- `diagnose vpn ike log-filter name <tunnel>` under `config global` is `command parse error`. Debug output comes to the session that turned it on, between the prompts, so a script that waits for a prompt stops (6.2.2).
- An interface's `tcp-mss` lowers the MSS of each SYN and SYN-ACK that arrives on it and is routed, IPv4 and IPv6, and leaves one that offers less as it is. With 1200 on the interface a SYN came in by and 1300 on the one it left by, the SYN left with 1200 and its SYN-ACK with 1300. With 1480, a SYN of 1460 left as it was. `show` prints the setting once set, and `unset tcp-mss` takes it away (6.2.2). A Fortinet community article says 7.0.1 clamps both ways instead.
- A DHCP server answers a relayed request from the server, of those on the interface it comes in on, whose network holds the relay's address, `giaddr`. Beside one for another network, the one for the relay's network answered, and alone, the one for another network didn't. A client asking on that interface itself got no address from a server for a relay's network, and got one from a server for the interface's own. A server's `ip-range` may lie outside its interface's network. There is no setting for the relay's own address: `set relay-agent` is `command parse error` (6.2.2). Fortinet's 7.4 CLI reference adds `relay-agent`.
- A DHCP server whose range overlaps one another server of its interface holds is refused at `next`: `object set operator error, -526 discard the setting`. So the plan knows a server by its interface, gateway, and mask, not its number, and deletes a server that goes before it creates or changes any (6.2.2).
- A link between VDOMs, `type vdom-link`, takes no DHCP relay and is no DHCP client: `set dhcp-relay-service` and `set mode dhcp` are `command parse error`. A VLAN interface on an NP6 link, such as `npu3_vlink0`, takes both. An interface of a VDOM other than the management VDOM has no `dns-server-override`, even in `mode dhcp`: `command parse error`, and the device's DNS servers stayed as they were (6.2.2).
