# FortiOS traps

Seen on a FortiGate 3700D running FortiOS 6.2.2, without a license.

- A change applies at `next` or `end`. With `cfg-save automatic`, the factory setting, it is saved at once. `abort` discards the changes to the one object being edited. Inside a table it is `Unknown action 0`, and entries already left with `next` stay applied.
- `cfg-save revert` keeps changes running but unsaved. `cfg-revert-timeout` seconds after a change, the device announces `System will reload` and reloads its saved configuration. This restarts the configuration, not the hardware, and takes about two minutes. `execute cfg reload` does it at once, without asking, and says `no config to be reloaded` when nothing is unsaved. `execute cfg save` saves, and so does setting `cfg-save automatic` again.
- `cfg-save revert` set while saving is automatic is saved itself. After a reload the device stays in revert mode. Every later change by hand is then undone after the timeout, until someone saves or sets `cfg-save automatic`. Circuit sets it back at the end of every apply.
- Circuit does not use `execute config-transaction start N` on 6.2.2: a candidate that `commit` applies and `abort` discards. Inside one, and only there:
    - Deleting an entry does not release what its lists point to. Deleting a policy, then the address it used, is refused: `The entry is used by other 1 entries`.
    - A transaction whose session is cut off keeps every object it touched locked for N minutes: `Can not config the object since it's being configured by another transaction`.
    - Editing a `firewall policy6` entry after `unset central-nat` ends the session at `edit`.
    - Deleting the user you are logged in as ends the session with `cmdb_txn_cache_data ... failed`. Every later transaction then fails until the device restarts.
    - `show` prints a new static route or policy with the comment of the last new one. The commit corrects it.
    - OSPF's `config redistribute` is refused: `config child object 'redistribute' is not handled in transaction`.
    - A certificate added in one cannot be used by name until the commit.
- The CLI pages long output with `--More--`. Once answered, it erases the prompt with spaces and a carriage return.
- A `?` typed anywhere shows help at once and is never sent. Ctrl-V before it types it literally.
- The idle timeout, `admintimeout`, is 5 minutes by default; the session then returns to `login:`.
- With `pre-login-banner` on, the console shows the banner and waits on `(Press 'a' to accept):` before `login:`. Circuit answers `a`.
- `grep` after a pipe takes no `-E`. A command ending in `| grep` prints its matches, then `Command fail. Return code -27`.
- `show` prints only settings that differ from their default, in its own order, not the order they were set. A new aggregate gets `device-identification enable` and `lldp-transmission enable` unasked. A new VLAN interface gets `device-identification enable` and `role lan`. Circuit unsets them.
- A port joins an aggregate only while nothing points to it, such as a static route: otherwise `entry not found in datasource`. A port in an aggregate cannot change speed, not even back to `auto`: `Interface speed cannot be set for aggregated interfaces`. So Circuit deletes what points to a joining port and creates it again after. A port whose speed changes leaves its aggregate and joins again. An aggregate that goes, or is left with no port, goes first, with what points to it.
- `unset secondary-IP` hides the list of secondary addresses and drops it. NTP's `unset type` hides its servers but keeps them: `set type custom` brings them back. NTP refuses to delete its last server while `ntpsync` is on. It refuses to empty the interfaces it serves on while `server-mode` is on: `There aren't any interfaces with NTP server enabled`. `unset server-mode` hides that list and lets go of its interfaces. The plan deletes a nested list before the setting that hides it, except `ntpsync`, which goes first.
- A DHCP server prints `dns-server1` only while `dns-service` is `specify`, the default, which `show` does not print. The factory server on `mgmt1` uses `default`, so the render writes `specify` before its resolvers.
- The timezone is a number of the platform's own, such as `53` for Jakarta, Bangkok, and Hanoi. The default is `00`, Eniwetok, at UTC+12; UTC is `80`.
- Global `alias` is set again at every start, whatever was saved.
- `log memory setting` prints its `status` whether on or off, and `unset status` turns memory logging on.
- Two interfaces that are up cannot have overlapping subnets: `Subnets overlap between ...`. An address that moves leaves the first interface before it joins the second.
- A static route identical to another is refused, even for a moment: `Duplicated entry`. Editing route 1 into what route 2 holds fails before route 2 changes. So a plan deletes every route that changes or goes before it creates any. Neither family prints a default route's destination.
- A deny policy gets `logtraffic disable`, and its action is not printed, since deny is the default. `send-deny-packet` exists only while a policy denies, and is `command parse error` otherwise. So the render writes `action deny` before it. A plan unsets it before `action accept` and sets it after `action deny`.
- `show` prints `unset` in two places: an ICMP service's `unset icmptype`, and a prefix list rule's `unset ge` and `unset le` for a bound it does not have.
- An SNMPv3 user authenticates with MD5 or SHA1 only. Only a community has hosts, not a user. Circuit decides who reaches every service with local-in policies instead.
- The console ignores a user's trusted hosts.
- A tunnel's interface takes an IPv4 address only as a host, with the far end in `remote-ip`. `set ip 10.0.0.1 255.255.255.252` on one is dropped without a word.
- A GRE or VXLAN tunnel creates an interface of its own, named after it, which goes when the tunnel goes. VXLAN has no local address: it leaves from the address of the interface it points to.
- A static route has no VRF of its own. It lands in the VRF of the interface it leaves through, as `get router info routing-table all` shows, so a blackhole route cannot go in a VRF. OSPF and BGP have no VRF setting.
- BFD's timers under `config system settings`, `bfd-desired-min-tx`, `bfd-required-min-rx`, and `bfd-detect-mult`, exist only while `bfd` is on there. `get` hides them otherwise. Their defaults, 250, 250, and 3, are not printed. So the render sets `bfd` before them, and a plan unsets them before `bfd`.
- A static route takes `set bfd enable`, IPv4 and IPv6, in a VRF too. The route stays in the table while its BFD session has never come up.
- BGP asks for a BFD session only once its session is up: `get router info bfd requests` lists nothing for a neighbor still `Active`, with `ebgp-enforce-multihop` or without.
- On a multihop BGP session BFD runs single-hop. It sends to UDP port 3784 and ignores the multihop BFD the peer sends to port 4784. Against a CCR2216 on RouterOS 7.23.5, `get router info bfd neighbor` stayed `DOWN` with remote discriminator `0`, and BGP flapped. `config router bfd` holds only single-hop neighbors. Circuit refuses BFD on a multihop session.
- The stateless ACL, `firewall acl` and `acl6`, only drops: it has no action.
- A route map stops at the first rule that matches, with no way to go on to the next. Its rules permit unless told to deny.
- `show vpn certificate local` prints a certificate without its text or key. `show full-configuration` prints both, the key encrypted.
- A private key the device cannot read gets `Invalid private key, password may be required`, with no `Command fail`, and the session goes on. A key whose lines end in CR LF gets the same answer, because the CLI takes each CR as a line. The certificate fails only at `end`: `Attribute 'private-key' MUST be set`.
- A GRE or VXLAN interface takes no flow sampler, and says so without `Command fail`: `Netflow sampler isn't supported on Tunnel interface..`, and the same for sFlow and for VXLAN.
- A port in an aggregate has no `icmp-send-redirect` (`command parse error`), and loses it when it joins one.
- `purge` empties a table after asking `(y/n)`.
- A VLAN interface has no LLDP settings: `set lldp-transmission` on one is `command parse error`. An aggregate's LLDP sends and receives on each of its ports.
- `diagnose lldprx neighbor summary` shows the FortiGate's own port as an index, `port 23` for `port5`. `diagnose lldprx neighbor details` gives the port's name in `port.txt`, and Circuit reads that. Both print nothing when no neighbor was received.
- A loopback has no MTU of its own and runs no VRRP. An interface's name has at most 15 characters.
- Multi-VDOM mode (`config system global`, `set vdom-mode multi-vdom`, `end`) asks `Do you want to continue? (y/n)` and logs every session out. Traffic keeps flowing: everything stays in `root`. From then on `system interface` lists `npu0_vlink0` to `npu3_vlink1`, two links between VDOMs for each NP6 chip, which cannot be deleted. Certificates (`vpn certificate local` and `ca`) and `log disk setting` belong to each VDOM, and are `command parse error` under `config global`. The system settings, interfaces, DNS, NTP, SNMP, syslog, sFlow, NetFlow, and session helpers are global, and are `command parse error` inside a VDOM.
- An interface moves into another VDOM (`config global`, `config system interface`, `set vdom`) only once nothing in its VDOM points to it, such as a static route. A session that came in on it stops answering once it moves, so move it from a session on another interface.
- There is no WireGuard and no RPKI: `command parse error`. A route map has no large community, a BGP neighbor no role, and SNMPv3 no SHA256.
- A BGP neighbor has `route-reflector-client` and `route-reflector-client6` only while it is internal. While the router's `as` is unset, or `remote-as` is another AS, setting them is `command parse error`. The render writes both ASes before them.
- `execute backup config flash <comment>` keeps a revision on the device, and `execute restore config flash <id>` restores one.
- The factory dedicates `mgmt1` and `mgmt2` to management, at `192.168.1.99` and `192.168.2.99`.
- On the serial console a line ends at a carriage return. A session left open stays logged in, and one left inside `config` stays there, so the next login must first leave and log out. The console runs at 9600 bits per second: reading the sections Circuit manages takes about two minutes.
- A data port can stay `netdev status: down`, with `rx_carrier: 0` in `diagnose hardware deviceinfo nic`, while the far end reads `link-ok` and frames reach the port's switch chip. Fixing the speed does not help, in a LAG or out of one; a reboot does. `link_status: Up` there means nothing: a port with no cable shows it too.
- Transparent mode, `set opmode transparent` under `config system settings`, needs a `manageip`: `Attribute 'manageip' MUST be set`. A link-local one, such as `169.254.0.1/255.255.255.255`, is accepted. Switching takes every interface's address away, replaces the static routes with one default gateway, and puts every port in one bridge. It deletes the factory's custom services, `ALL` among them, so a policy that uses `ALL` is refused: `entry not found in datasource`. It also adds an empty static route in each family and turns memory logging on, so an apply that switches the mode plans once more after it.
- `forward-domain` exists only in transparent mode: in NAT mode it is `command parse error`. VLAN interfaces in the same forward domain are bridged, and each frame leaves with the tag of the interface it leaves by.
- Leaving transparent mode, `set opmode nat`, is refused with `IP address must be a class A, B, or C ip` unless an address is given with it.
- A VLAN interface holds its VLAN ID and parent alone. A new one on the same pair is refused: `vlanid and underlying interface must be a unique pair`. So a rename deletes the old one first, with the routes and policies that use it, and makes them again under the new name.
- `config system proxy-arp` takes one entry per address, `set interface` and `set ip`, and is printed empty when it has none.
