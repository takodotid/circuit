# Raisecom ROS traps

Seen on a RAX721 running ROS 6.5.2 (product version P300R003C00). Raisecom's public guide is for P200R003 and differs in places.

- Commands apply as they arrive and persist only on `write`.
- The SSH server offers only an `ssh-rsa` host key. The adapter allows it for this platform alone; key exchange, cipher, and MAC still negotiate modern ones.
- `show running-config` stops about halfway, with no error, unless `terminal page-break disable` is sent first. Even then it can stop partway: three reads of an unchanged switch in a row gave plans of 62, 0, and 158 commands. On a lossy path (5 to 25% loss, #86), a TCP retransmit can stall the dump for several seconds. So the read waits for the dump to end at the prompt, up to 30 seconds of silence and 150 seconds in all, and reads again if it doesn't. After three tries the read fails rather than plan against a part.
- A `?` sent by a script is executed: once it applied an address with a /8 mask. Tab after a word the CLI does not know answers `Error input`, as if the line were sent. To test whether a keyword exists, send the whole line with a made-up ending: the caret under `Error input` marks how far the CLI took it, and nothing before it applies. It shows a range too: a value out of range gets the caret. A line whose last value is free text takes the made-up word as that value and applies: `ip as-path access-list 1 permit _64496_ zzqq` set a list, and `key-chain zzqq` made a key chain. The caret also finds keywords one letter at a time: `ipv6 nd ra a zzqq` puts it after `a` when a keyword starts with `a`.
- An answer can come after the next line is sent, so a line seems to answer nothing and the next one answers for both. Wait for the prompt before sending the next line.
- Some refusals carry no error word: `IP address overlaps with configured interface.`, `Malformed community-list value.`, `Parameter is error.`, `Route target is illegality.`, `Can't find community-list.` The apply treats each as refused.
- An access-list cannot change while any service uses it: `ACL 1000 is in use`. Every service that uses it is unbound first and bound again after. `no ssh2 access-list` needs the list number.
- `portswitch`, `switchport trunk allowed vlan`, and `switchport mode` ask for `y` and do nothing without it. `portswitch` asks on a port already switched too. The exception is a command that needs no confirming: `switchport mode trunk` on a port leaving access mode answers `Set successfully` at once, and a `y` sent after it is refused, `Error input`.
- `create vlan <list> active` has every VLAN on one line. A VLAN is removed with `no vlan <id>`, not `no create vlan`. A change creates only the new VLANs and removes each one that is gone.
- `no storm-control mode` is refused with `Error input`. The modes are `kbps`, the default, which prints nothing, and `pps`; leaving `pps` is setting `kbps`.
- A port's speed or duplex set to something else and back to auto prints `speed auto` and `duplex auto` from then on, though auto is the default. `no duplex auto` is refused with `Error input`.
- The factory account `raisecom` cannot be removed and its service type cannot change. Circuit manages only its password.
- Factory SNMP communities survive hardening, and `private` can write. The render removes both.
- Some commands are spelled unusually: `terminal page-break disable`, `telnet-server disable`, `ip rarp server disable`.
- An access-list description takes one word. A space is refused with `Error input`.
- The out-of-band port `fastethernet 1/0/1` cannot be shut down and is not in the catalog.
- A LAG is `interface port-channel N`. LACP is its default and prints nothing; a static LAG prints `mode manual`. The LAG takes layer 2 settings only after `portswitch`, and a port joins with `portswitch` then `port-channel N`.
- An SNMPv3 user prints as localized keys, `authkey sha <hex> privkey  aes128 <hex>`, which authenticate as well as the passphrase. The read redacts them. An access group prints a `notify internet` it was not given. A user's group is removed with `no snmp-server group user <user> usm`.
- A VRRP group is enabled once it has an address and preempts unless `no vrrp N preempt`. `no vrrp N ip <address>` removes the whole group.
- OSPF settings for an interface sit on the interface: `ip ospf cost`, `ip ospf network ptp`, `ip ospf passive-interface enable`. Passive is undone with `... disable`, not `no`.
- A link's hello interval prints only when it is not the link's own, 10, or 30 on an NBMA link, and the dead interval only when it is not four hellos. Priority 1 prints nothing. `ip ospf network` sets the hello and dead intervals back to its type's own, so the plan sends them again after it. Set before a new type, a dead interval stays as the wait interval and prints as `ip ospf wait-interval N`.
- An NBMA link is `ip ospf network non-broadcast`, with each neighbor as `neighbor <address>` in the process. There is no point-to-multipoint link: `p2mp` and `point-to-multipoint` are `Error input`. There is no virtual link, and a range takes `not-advertise` and no cost: `area <id> range <address> <mask>`.
- OSPF signs with MD5 or a simple password: `ip ospf authentication md5` and `ip ospf authentication-key md5 <1-255> 0 <key>`, which prints the key in clear. The read hides it. With `7`, the key must be a cipher: `The lenth of password is error.`
- A loopback takes no `ip ospf` setting: `ip ospf passive-interface` there is `Error input`. OSPF treats it as a stub host by its `network` line.
- The OSPF process prints its lines in an order of its own, each with one space before it. The area types, ranges, timers, priority, NBMA links, and keys above were applied to a spare port, a loopback, and two VLANs with no ports, read back, and planned empty, but never removed one by one, so Circuit sends them with `--experimental` only.
- OSPF in a VRF is `router ospf 1 vrf <name> router-id <id>`, which took the settings above and planned empty. On 2026-11-26, tako-mmr-01 restarted one to two minutes after a plan removed it with `no router ospf 1`, which answered `Set successfully.`, and then the VLAN interfaces and the loopback in its VRF. The process seemed to outlive the line: removing the loopback after it logged `Process 1 (vpn-instance ctest), Interface loopback1 ... is Disabled`. The log names no cause, and the next boot began with `The one of dual power2 supply is down`. Circuit refuses OSPF in a VRF until the cause is known.
- An access-list rule is not replaced by one with the same number: the device answers `Set unsuccessfully.` and keeps the old rule. The old one is removed first. `no rule N` takes a second or more to answer.
- `show lldp remote` shortens port names (`TGE1/3/3`, `100GE1/1/4`) and pads its columns, so a system name with a space cannot be told apart. The read uses `show lldp remote detail`, which spells each port in full. A long value there wraps mid-word onto a line that starts with spaces.
- `hostname <name>` is refused in configuration mode (`Error input`) and taken only at the `#` prompt, so the plan leaves configuration mode to send it. It prints among the `enable_mode` lines. An unset hostname prints nothing, and the switch then sends `Raisecom` as its LLDP system name.
- `user name <user> password <password>` and `enable password` are refused in configuration mode too (`Error input`, the caret after `u` or `en`). A user is taken at the `#` prompt, where `user login`, `radius`, and `tacacs-server` are too, and so is `enable password` in the guide, which asks for the password twice unless given `cipher`; it was not sent to a switch in service. They print among the `aaa_mode` and `enable_mode` lines. A user goes with `no username <user>`: `no user name <user>` is refused at the name. A new user has no `service-type` to set here: `user <user> service-type ssh` is refused at `service-type`. So the plan sends users and the privileged password at the `#` prompt, as it does the hostname.
- A Junos neighbor sends its SNMP index as its port, `PortId: 520`, and its description as `PortDesc`, unless it is set to send the port's name (see the Junos traps). The read keeps the number, which matches no `link`.
- `snmp-server access-list 1001` adds a list beside `1000` rather than replacing it, and SNMP then holds both. The plan binds the new list first and then sends `no snmp-server access-list 1000`, so SNMP is never left without one. SNMP's own sources are access-list 1001.
- `logging host <ip>` takes a level by name (`warnings`) or number, and a port as `udpport <n>`, level first. `logging host <ip> udpport <n> warnings` is refused with `Error input`, and so are `port` and `udp-port`. It prints the level as a number and leaves out level 6 and port 514: `logging host 192.0.2.50 4 udpport 5140`. A second `logging host` for the same address changes it in place. `no logging host <ip>` removes it whatever its level and port.
- Port security takes only a switched port: `switchport port-security` on a port without `portswitch` is refused with `Error input`. Its maximum is 1 to 1024; 1024 is its default and prints nothing. At the limit it drops (`protect`), and learned addresses age out after 5 minutes. `no switchport port-security maximum` takes no number.
- A MAC access-list is `access-list 3000` and up. A rule's ethertype is hex without `0x`: `0x86DD` is refused with `The EtherType is INVALID!`, and `2054` is 0x2054, not ARP. `0800` and `0806` print as `ip` and `arp`, any other as `86dd ffff`. A port binds it with `filter ingress access-list N`, which answers nothing, also on a port without `portswitch`.
- A MAC access-list a port filters with cannot change: `ACL 3000 is in use, and it can not be modified or destroyed`. Each port has its own list, 3001 and up by its place in the catalog. The plan unbinds the port, changes the list, and binds it again.
- `no portswitch` asks for `y` like `portswitch`. A port the plan switched stays switched when it goes back to unused, which the read cannot see.
- OSPF BFD is `ip ospf bfd` on the VLAN interface, printed as sent and undone with `no ip ospf bfd`.
- A static route is watched by a BFD session. `bfd N bind peer-ip <next hop> interface vlan <V>` opens the session's view, where `session enable` starts it. It prints under `!command in bfd_template_mode`, with `session enable` indented, and goes with `no bfd N`. The route takes it as `ip route <prefix> <mask> <next hop> track bfd N` and prints `track bfd-session N`. `no ip route <prefix> <mask> <next hop>` removes the route whatever it tracks. A route takes a session number that does not exist yet. Only one session binds to a peer: a second one's `session enable` answers `Error input`, so the old session goes before the new one is made.
- BFD timers are global: `bfd detect-multiplier N`, `bfd send-interval N`, and `bfd receive-interval N`. `send-interval` took 10 and refused 300 and 99999, so its unit and range are not known. Circuit refuses `routing.bfd` here.
- A second SSH login right after another one often timed out at the handshake. One after a pause of about 15 seconds did not.
- Spanning tree runs MSTP. A port's edge setting is `spanning-tree edged-port force-true`, `force-false`, or `auto`, the default, which finds edge ports by itself; `no` is refused. Root guard is `spanning-tree rootguard enable`, undone with `... disable`. A port's priority prints as `spanning-tree instance 0 priority N` and goes with `no spanning-tree instance 0 priority`. The switch's own priority was not tried.
- BPDU guard is one setting for the switch, `spanning-tree bpduguard enable` or `disable`, and guards every edge port; there is no `no` form and no setting on a port. The guide says it shuts down an edge port a BPDU reaches. On a live switch only its syntax was tried, so Circuit sends it with `--experimental` only.
- A port has two path costs, `spanning-tree inter-path-cost` inside the MST region and `extern-path-cost` outside it. Circuit refuses `stp.cost`.
- Storm control takes `broadcast`, `multicast`, and `dlf` (unknown unicast), 1 to 262143 pps. The P200 guide's `unknown-multicast` is refused, so which multicast `multicast` limits is not known, and Circuit refuses it. `no storm-control dlf` takes no number.
- `rate-limit ingress|egress cir <kbit/s> [cbs <kB>]` limits a port or a LAG. Without `cbs` the switch takes one second at the rate, at most 4096 kB, and prints no `cbs`; a `cbs` the same as that prints none either. `cir` takes 0 to 100000000 and `cbs` 0 to 4096. A rate above the port's speed answers `Exceed the actual bandwidth of the interface.`, with no error word, so the apply treats `Exceed` as refused. `no rate-limit ingress` takes no rate.
- QinQ is `dot1q-tunnel` on an access port, which prints with a space at the end. The outer tag is 0x8100, the default, and prints nothing.
- A port's TPID is `tpid 88a8`, hex without `0x`: `tpid 0x88a8` is `Error input`. It goes with `no tpid`, and `no tpid 88a8` is refused at the value. `show interface` then says `TPID 0x88a8`, but `show dot1q-tunnel` kept saying 0x8100 for the port. The guide sets it on a port, not a LAG: a trunk and a QinQ port took it.
- VLAN translation is `switchport vlan-mapping both outer <from> translate <to>` on a trunk, which prints with two spaces at the end. It goes with `no switchport vlan-mapping both outer <from>`: with `translate`, the caret marks it.
- DHCP snooping is off for the switch and on for each switched port, so `ip dhcp snooping` snoops on every switched port at once. On a live switch only its syntax was tried. `ip dhcp snooping trust` on a port prints as sent and goes with `no`.
- ARP inspection is `ip arp-inspection dhcp-snooping` for the whole switch, against the bindings DHCP snooping learns, in every VLAN: `show ip arp-inspection` says `Protect Vlan : 1-4094`, and `ip arp-inspection vlan` is `Error input`. Every port is untrusted until `ip arp-inspection trust`, which prints as sent and goes with `no`. On a switch in service only the switch's line was parsed, so Circuit sends ARP inspection with `--experimental` only.
- IP source guard is one setting for the whole switch, `ip verify source` for bindings written by hand or `ip verify source dhcp` for those DHCP snooping learns, and `show ip verify source` lists every port untrusted until `ip verify source trust`. Once on, a port drops IP from any host without a binding, so turning it on would cut every port in service that is not trusted first. It checks no ARP and no MAC address. Circuit refuses `bound_to`.
- There is no RA guard. `ipv6 nd snooping` turns ND snooping on for the switch, a VLAN (`vlan N` opens its view), or a port, where it takes `trust` and `check rs` and nothing for router advertisements.
- A private VLAN is `private-vlan primary vlan N` and `private-vlan isolated vlan N`, one line for each VLAN, while every community VLAN prints on one line, `private-vlan community vlan 3992-3993`, and `private-vlan association <primary> <secondaries>` ties them. A host port is `switchport mode private-vlan host` with `switchport private-vlan host-association <primary> <secondary>`, and a new host-association replaces the old. A promiscuous port is `switchport mode private-vlan promiscuous` with `switchport private-vlan mapping <primary> <secondaries>`, which a trunk takes too; `switchport private-vlan trunk` is `Error input`. The mapping, the host-association, and the association go by their keyword and the primary alone: with the rest, the caret marks it. `no switchport mode` is refused, and `switchport mode access` ends either mode. Applied to spare ports, read back, changed, and removed, but no frame crossed them, and the guide doesn't say whether a trunk or a VLAN interface reaches an isolated host, so Circuit sends private VLANs with `--experimental` only.
- An extended access-list is `access-list 2000` to `2999` for IPv4 and `7000` to `7999` for IPv6; `6000` and up is a standard IPv6 list, `4000` MPLS, `5000` user-defined, and `8000` and `9000` advanced. A rule is `rule N permit|deny <protocol> <source> [<port>] <destination> [<port>]`, an IPv4 source as an address and a mask, an IPv6 one as a prefix, which prints in capitals. A rule takes one port: `eq` and `range` are `Error input`, and a port needs `tcp` or `udp` by name, as `6 any any 22` is refused at the port. Protocols 6, 17, 1, and 58 print by name, the rest as numbers. A rule takes no description. A rule whose match repeats another's answers `Conflict with previous rule of current ACL.`, with no error word. A port takes an IPv4 list and an IPv6 list side by side. No traffic crossed one, so what the firmware does with a packet no rule matches is not known: Circuit ends each list with `rule 65535 permit ip any any`, or `ipv6`.
- A list's name, `access-list N name <name>`, is one for every list: a second list with it answers `Acl name has existed.`, with no error word, and stays in configuration mode, so the rules after it are refused there. A list goes by its number: `no access-list N name <name>` is refused at `name`.
- There is no bridge interface: `interface bridge` is `Error input`. `interface vlan <id>` takes no second tag, so no VLAN interface ends an inner VLAN.
- The switch answers NTP queries, at stratum 3, with only `ntp enable` and `ntp server` set. The guide's one setting for a server, `ntp refclock-master`, serves its own clock and refuses `ntp server` beside it.
- A trap receiver is `snmp-server host <address> version 3 authpriv <user>` or `... version 2c <community>`, with `udpport <port>` after for a port other than 162, which prints nothing. An IPv6 receiver prints in capitals, `2001:DB8::162`, and a community prints in clear, so the read hides it. `show snmp config` says traps are on by default. A receiver goes with `no snmp-server host <address>`: with the rest of the line, the caret marks `version`.
- A DHCP server is a pool, `ip dhcp server pool <name>`, 16 characters at most, holding `address <first> <last> mask <mask>`, `gateway`, `dns-server`, `dns-server <address> secondary`, and `lease expired <minutes>`, 30 to 10080, and `ip dhcp server` on the VLAN interface it serves. A new `address` or `gateway` replaces the old: `no address` is refused, and `no gateway`, `no dns-server secondary`, and `no lease expired` take no value. A reservation is `ip dhcp static-bind <address> <mac> <pool>`, with the MAC as `0200.0000.0001`, and goes with `no ip dhcp static-bind <address> <mac>`. A pool with a reservation refuses any change, `Please delete the static bind of the pool`, with no error word, so the plan lets the reservations go and binds them again after. No client asked one for an address, so Circuit sends a DHCP server with `--experimental` only.
- A DHCP relay is `ip dhcp relay` and `ip dhcp relay target-ip <server>` on a VLAN interface, each printed as sent, and `ip dhcp relay` and `ip dhcp relay information option` for the whole switch, which `show ip dhcp relay` showed off. On a switch in service only the interface's lines were applied, as the switch's may take DHCP from every VLAN, so Circuit sends a relay with `--experimental` only.
- ROS 6.5.2 has no sFlow, NetFlow, or IPFIX, no web server (`ip http`, `http`, `https`, `web`), and no certificate store (`pki`, `crypto`, `ssl`): each is `Error input`. `show sla` lists operations of Ethernet (Y.1731), MPLS, and TWAMP, none of ICMP echo. `show ssh2 server` shows NETCONF on, on port 830, whatever is set, and Circuit doesn't turn it off.
- QoS is `mls qos` for the switch, `mls qos trust dscp` or `cos` and `mls qos priority` on a port, `mls qos mapping dscp-to-local-priority` and its kin, and `class-map`, `policy-map`, and `service-policy`. Neither the switch nor a port takes `mls qos queue`, so where a port's queues are scheduled is not known. Circuit doesn't build QoS here yet.
- `ssh2 server authentication` takes one method for every user, `password` by default. The guide gives a client's public key a name of its own and no user, so Circuit refuses `ssh_keys`.
- A port without `portswitch` is a routed port, `Route Port` in `show interface`, and takes `ip address`. `no portswitch` asks `All subinterfaces will be deleted by this configuration, Please input 'y' to confirm`. The read leaves `portswitch` out, so the plan sends `no portswitch` to a port the device has switched before it gives the port an address.
- A loopback is `interface loopback N`, 1 to 1024: `interface loopback 0` is refused. An address that overlaps another interface's is refused with `IP address overlaps with configured interface.` An address goes with `no ip address <address>`: without the address it is `Incomplete command`, and with the mask the caret marks the mask.
- A route names its interface after the next hop, `ip route <prefix> <mask> <next hop> tengigabitethernet 1/3/24` or `... vlan 3999`, and prints with a space at its end. A LAG or a loopback there is refused, and so is an interface without a next hop, but `null 0`, which prints as `NULL 0`. A route through a VLAN interface that does not exist yet is refused, so the plan adds routes after the interfaces. `no ip route <prefix> <mask> <next hop>` answers `Set successfully.` and keeps a route with an interface, so the undo gives the interface too.
- A VRF is `ip vrf <name>`, printed alone with `!` after it, and takes no description: `description` there is `Error input`. An interface joins it with `ip vrf forwarding <name>`, which answers `All IP related configurations on this interface are removed.` and does it, so the plan sends the interface's IP settings again after it. `no ip vrf forwarding` takes no name: with one, the caret marks it. A route in it is `ip route vrf <name> ...`.
- uRPF is `ip urpf strict` or `ip urpf loose` on an interface, and `ipv6 urpf` the same, each printed as sent. `no ip urpf loose` is refused with the caret at `loose`, so it goes with `no ip urpf`, which was not run: the switch restarted before the removal reached it. Circuit sends uRPF with `--experimental` only.
- IPv6 router advertisements have no setting that turns them on or off. `ipv6 nd ra` takes `hop-limit`, `interval` (4 to 1800), `managed`, `other`, `prefix <prefix> <valid> <preferred> [no-autoconfig]`, `router-lifetime` (0 to 9000), and `advlinkmtu`; `managed` and `other` print as `managed-config-flag` and `other-config-flag`. `show ipv6 nd ra` showed them `off` on a VLAN interface with an IPv6 address and each of them set, and no interface with IPv6 was up to see whether one sends them. So Circuit refuses `ipv6_ra`, and an IPv6 address, which could send them unasked.
- BGP is `router bgp <asn>` with `bgp router-id`, `bgp cluster-id`, `bgp graceful-restart`, `network <address> <mask>`, `aggregate-address <address> <mask> [summary-only]`, and a session's `neighbor <address>` lines: `remote-as`, `description`, `update-source <address>`, `ebgp-multihop`, `password`, `timers`, `fall-over bfd`, `route-reflector-client`, `default-originate`, `send-community`, `route-map <name> in|out`, and `shutdown`. A session's password prints in clear. There is no `maximum-prefix`, `ttl-security`, `passive`, or `bgp confederation`. The process prints an `address-family` block for `ipv6`, `vpnv4`, `vpnv6`, and `l2vpn evpn` whatever is set, the last three with `policy vpn-target`, and `exit` leaves an address family for the process. Circuit does not build BGP yet.
- A route-map entry takes `description`, `match ip address prefix-list`, `match ipv6 address prefix-list`, `match community`, `match as-path <number>`, `match origin`, `match metric`, `set local-preference`, `set metric`, `set as-path prepend`, `set community ... [additive]`, `set community none`, `set comm-list <name> delete`, `set ip next-hop`, `set origin`, and `call`. There is no `continue`, no `on-match`, no large community, and no `global` in `set ipv6 next-hop`. `ip prefix-list` and `ipv6 prefix-list` take `seq`, `ge`, and `le`, and `ip community-list` is `standard` or `expanded`. `ip as-path access-list <number> permit <regex>` takes the rest of the line as its regex. Circuit does not build route policies yet.
- IS-IS is `router isis <n>` with `net`, `is-type level-1|level-2-only|level-1-2`, `metric-style wide`, `set-overload-bit`, `area-password md5|clear <key>`, `domain-password md5 <key>`, and the leak `redistribute isis ip level-2 into level-1 route-map <name>`, each printed with two spaces before it. There is no multi-topology. An interface takes `ip router isis <n>`, `isis metric`, `isis passive`, `isis network point-to-point`, `isis bfd enable`, and `isis password md5 <key>`, and the passwords print in clear. `ip router isis 2` makes process 2 when it does not exist, an interface in one process refuses another with `The interface is already attached to the other process.`, and leaving a process removes the interface's `isis` lines. Circuit does not build IS-IS yet.
