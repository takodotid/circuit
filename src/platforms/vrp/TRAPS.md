# VRP traps

Seen on a CE6855 running V200R005.

- Changes stage in a candidate and apply at `commit`. `commit` does not write to flash; without `save` a reboot restores the old configuration. `save` asks `[Y/N]`.
- An ACL bound to a service with no rules denies everything, including the session doing it. Rules and binding go in one commit.
- The first login asks to change the password. Answering Y replaces it at once and invalidates every stored credential; always answer N.
- SSH negotiates an ECDSA host key it then signs wrongly, so the handshake fails. Pin `ssh-rsa`.
- Connections in quick succession are refused before authentication for a while. Connect one at a time.
- Accounts lock after a few failures and the last ten passwords are refused. A retry loop locks the account out.
- A `?` sent by a script is executed, not treated as help. Never send one.
- A refused line's caret counts the prompt: its column minus the prompt's length is where the command stopped making sense.
- `stp bpdu-protection` exists only in the system view, for every edge port at once; in a port's view it is `Unrecognized command`. There is no RA guard: `ipv6 nd raguard`, `ipv6 raguard`, and `nd raguard` are refused in every view. DHCP snooping is `dhcp enable` and `dhcp snooping enable`, then `dhcp snooping enable` or `dhcp snooping trusted` in a port's view (in a candidate, never committed). `arp anti-attack check user-bind enable` is `Unrecognized command` in a port's view and taken in a VLAN's view. MUX VLAN is `mux-vlan`, `subordinate separate <id>`, and `subordinate group <id>` in the principal VLAN's view, then `port mux-vlan enable vlan <id>` in a port's view; without `vlan <id>` it is `Incomplete command`.
- `reset saved-configuration` erases the management address. Never over the network.
- The prompt shows commit state: `[~host]` clean, `[*host]` uncommitted. Read `display configuration candidate` when in doubt.
- LLDP is off by default. A port setting for LLDP is refused until it is on globally.
- A trunk forwards its native VLAN's untagged frames only when that VLAN is also allowed; the adapter adds it.
- The name `admin` is refused for a local user.
- A port joins an Eth-Trunk only while it has no other setting, including a description.
- An empty block such as `bfd` enters its view; the next line sent goes into it unless the view is left.
- SNMPv3 passwords are asked for interactively, twice. `authentication-mode` must come before `privacy-mode`.
- `abort` is not a command here. `clear configuration candidate` discards uncommitted changes.
- sFlow samples per port, `sflow sampling rate N`, N from 4096; the default is 8192 and an explicit 8192 is kept as written. A port can point to a collector only once the collector exists globally; until then it is refused with "collector does not exist".
- `vlan batch` has every VLAN on one line, and undoing a list that includes a VLAN with an L3 interface is refused. A change sends only the VLANs added and `undo vlan batch` for the ones removed.
- A VLAN name is unique across VLANs: a new VLAN cannot take a name another still has. VLANs no longer used, and their VLAN interfaces, are removed first, in the same candidate.
- `undo ssh server key-exchange <algorithms>` is refused with "Too many parameters"; `undo ssh server key-exchange` takes none. `hmac` behaves the same. `cipher` is undone the same way but was not tested on its own.
- A console on a password only (`password_only`) shows `Please Press ENTER.` after a logout or a refused password, and `Error: The password is invalid.` for a wrong one.
- Once SNMP is on, the switch prints an engine ID of its own, `snmp-agent local-engineid`, derived from its MAC, which the read ignores. It prints each SNMPv3 user as a bare `snmp-agent usm-user v3 <name>` line before its settings, which the render writes too (V200R005C00SPC800).
- `apply --secrets` sends every line holding a secret again, the local users' passwords included. A password among the user's last ten is refused, which discards the whole candidate. Send it only when a password changed.
- An SNMPv3 key prints as `cipher %^%#...%^%#`, which can be turned back into the key. The read redacts every value after `cipher`, as it does a password.
- `display configuration candidate` shows the uncommitted lines as they were sent, not as the switch prints them. Commit to see the printed form. `display configuration candidate merge` prints the running configuration with the candidate in it, in the printed form, without a commit (V200R005C00SPC800).
- An ACL bound to a service cannot be removed: `undo acl number N` is refused at once with "This ACL is being used.", even when the same candidate already moved the binding. ACLs no longer used are removed last.
- An ACL rule sent over a rule of the same number merges into it: `rule 10 deny` over `rule 10 permit source A` leaves `rule 10 deny source A`. A changed rule is undone first.
- A single source address prints its wildcard as `0`: `rule 5 permit source 192.0.2.1 0`.
- `snmp-agent group v3 <group> ... acl N` sent again with another ACL replaces the binding in place.
- A log host line sent again changes only the options it gives: `info-center loghost A port 514` over `level informational` keeps the level. A log host that loses an option is undone first. Its undo takes the address alone, `undo info-center loghost A`; `level ...` after it is refused with "Too many parameters".
- Defaults are not printed: a log host's `level debugging` and `port 514`, the log files' level `debugging` (channel 9), and `info-center max-logfile-number 200`. The file count is 3 to 500. Every log host line warns "non secure syslog protocol" and is still taken.
- `undo info-center source default channel 9` turns the log files' default source off and prints as that line; `info-center source default channel 9` puts it back. Circuit undoes the level alone: `undo info-center source default channel 9 log level`.
- An alarm's severity prints with a capital, `alarm hwOpticalUnAuthorized severity Warning`, in the `alarm` view. A new severity replaces the old in place. `undo alarm` is not a command: `undo alarm <name> severity` takes no value, and the view goes once it is empty. An alarm raised before the change keeps its old severity in `display alarm active`. An unknown alarm name is refused with "Wrong parameter".
- `ospf bfd enable` starts with `ospf` like the `ospf 1` header, but opens no block. Only `ospf <number>` does.
- BFD intervals are 50 to 1000 ms and the multiplier 3 to 50; anything else is "Wrong parameter". `detect-multiplier 3` is the default and is not printed.
- `ospf bfd min-tx-interval ...` sent again changes only the options it gives: an old `detect-multiplier 50` stays. Changed timers are undone first; the undo takes the whole line.
- A static route watched by BFD needs a template for its next hop first, `ip route-static bfd <next hop> local-address <own address>`. Without it the route is refused with "The bfd parameter template does not exist". The template sent again replaces the old one whole, and is undone by its next hop alone, `undo ip route-static bfd <next hop>`.
- A static route prints `preference`, `description`, then `bfd enable`. Its undo takes the destination and next hop alone; `preference` after them is refused with "Too many parameters".
- A port's MAC limit is `mac-address limit maximum N`, also taken as `mac limit maximum N`. The default action, discard, and the alarm are not printed. The line sent again changes only the options it gives. Its undo takes no value, `undo mac-address limit`. `mac-limit` and `port-security max-mac-num` are not commands here, and `mac limit` is refused while `port-security enable` is on.
- A layer 2 ACL (4000 and up) rule sent as `permit l2-protocol 0x0800` prints as `permit type ip`, and `0x86dd` and `0x0806` as `type ipv6` and `type arp`. The printed form is taken as sent. A port applies it with `traffic-filter acl N inbound`; `traffic-filter inbound acl N` is not a command.
- `display lldp neighbor` lists every port with LLDP on, the management port too: `10GE1/0/2 has 1 neighbor(s):` or `has 0 neighbor(s)`. A port with `lldp disable` is not listed. `Port ID` comes before `System name`, and some values end in spaces. The brief form puts each neighbor on one line in fixed columns, so the full form is read.
- SSH keys (V200R005C00SPC800):
    - The switch takes RSA, DSA, and ECC (ECDSA) keys only: `display ed25519 peer-public-key` is `Unrecognized command`.
    - `rsa peer-public-key <name> encoding-type openssh` takes the key's text in `public-key-code begin`. A whole RSA 4096 key on one line is `Total length of input over the allowed length`; lines of 200 are taken and joined.
    - Once committed it prints the text in lines of 80, ending with ` rsa-key`, its own comment, before `telnet server disable`.
    - A user takes one key, `ssh user <user> assign rsa-key <name>`. `undo ssh user <user> assign rsa-key` lets go of it, without the name; with it, `Too many parameters`.
    - `authentication-type all` takes the key or the password.
    - `undo rsa peer-public-key <name>` asks nothing once no user has the key. `rsa peer-public-key <name>` again, while it exists, asks `Do you really want to replace it? [Y/N]`.
- A line the current view refuses runs in the view above it. `qos car inbound cir 200000 cbs 250000` in a port's view left the view, and the system view took it as a CAR profile named `inbound`. A port polices what arrives through a profile: `qos car <name> cir <kbit/s> cbs <bytes>` in the system view, then `qos car inbound <name>` in the port's view. What leaves is `qos lr cir <kbit/s> cbs <bytes> outbound`; `qos lr outbound cir ...` is `Unrecognized command` (in a candidate, never committed).
- `commit trial <seconds>` commits until the time runs out, then rolls back by itself. `abort trial` is `Unrecognized command`. A `commit` during the trial asks `The trial configuration will be confirmed. Continue? [Y/N]` (V200R005C00SPC800).
- Logins through servers (V200R005C00SPC800, servers unreachable):
    - The administrators' default domain can't be removed while an administrator is online, as Circuit's own session is: `undo domain` answers `There are online users in the domain`, even after `undo default-domain admin` in the same candidate. Circuit gives the switch's own default, `default_admin`, its schemes and servers, and takes them away again, rather than make a domain.
    - A line that points to a scheme is checked as it arrives: `cmd recording-scheme circuit` before the scheme exists is refused with `The recording scheme does not exist`.
    - A domain lets go of a scheme, a server group, or its level by the keyword alone, `undo radius server group`; with the name, `Too many parameters`. `cmd recording-scheme` is undone without its name too.
    - A primary RADIUS server is undone by its kind alone, `undo radius server authentication`; with its address, `Incomplete command`. A secondary is undone by its address, port, source, and `secondary`, without its key. Servers print in the order they were added, so a change sends them all again. A change to a group in use was taken in a candidate but never committed.
    - Keys print as `shared-key-cipher %^%#...%^%#` and `shared-key cipher %^%#...%^%#`, which the read redacts. A TACACS+ server on port 49 prints without it.
    - With `authentication-mode local radius` or `local hwtacacs`, the switch's own user logs in with its password at once.
- A question the switch asks takes the next line sent as its answer, whatever it is: a `peer ... timer` line took the `peer ...` line after it as no, and `commit trial` during a trial took the line after it as yes, which confirmed the running trial. `display clock` was taken as yes, and `interface Vlanif3999` and `display configuration candidate` as no. Circuit answers each question itself (V200R005C00SPC800).
- `quit` from the system view with lines in the candidate asks `Are you sure to commit them before exiting? [Y(yes)/N(no)/C(cancel)]`. Send `clear configuration candidate` before leaving.
- BGP and route-policies (V200R005C00SPC800, each committed with `commit trial`, the next plan empty, then removed):
    - V200R005 has no large communities (`ip large-community-filter`, `if-match large-community-filter`, `apply large-community` are `Unrecognized command`), no `goto next-node`, no `route-policy <name> address-family mismatch-deny`, and no `apply ip-address next-hop blackhole` (`Wrong parameter`). `if-match as-path length` takes no length: `Too many parameters`.
    - A peer created with one AS refuses another: `peer <address> as-number <new>` is `The peer already exists in AS <old>`. Circuit removes the peer with `undo peer`, which asks `[Y/N]` and takes every line of the peer, then writes it whole again.
    - `peer ... timer`, `peer ... enable` in the IPv6 family, `undo peer`, and `undo bgp` ask `[Y/N]`.
    - An IPv4 peer is enabled in `ipv4-family unicast` on its own and prints `peer <address> enable` there. An IPv6 peer is enabled by hand.
    - IPv6 addresses print in capitals: `peer 2001:DB8::1`, `network 2001:DB8:: 32`. An IPv4 `network` prints its mask, `network 203.0.113.0 255.255.255.0`, even when sent with a length.
    - A prefix list entry sent with `less-equal` alone prints its lower bound too, `203.0.113.0 24 greater-equal 24 less-equal 32`, unless the length is 0: `:: 0 less-equal 128`. An exact entry, `192.0.2.0 24`, prints as sent.
    - A well-known community prints by its name: `permit 65535:65281` prints as `permit no-export`. `65535:666` prints as a number.
    - `undo route-policy <name> node <number>` takes no `permit` or `deny`. Entering a node that exists answers `Info: This sequence is being overridden.` and keeps its lines.
    - Several `if-match community-filter` lines stay in one node, each its own line.
    - Without `peer ... advertise-community`, a peer is sent no communities (the CloudEngine command reference). Circuit writes it for every peer.
- Traffic filters and ACLs (V200R005C00SPC800, committed with `commit trial` on a spare port, the next plan empty, then removed):
    - An ACL takes a name, `acl name <name> advance`, and an ACL6 the same name, `acl ipv6 name <name> advance`. A port takes one of each: `traffic-filter acl <name> inbound` and `traffic-filter ipv6 acl <name> inbound`, printed with a space after them. `undo acl name <name>` removes one, after the port lets go of it.
    - A layer 2 ACL and an IPv4 ACL on one port replace each other: `traffic-filter acl 4990 inbound` after `traffic-filter acl <name> inbound` left only the first.
    - A rule prints a well-known TCP or UDP port by its name, in an ACL6 too: `eq 179` prints as `eq bgp`, UDP 53 as `dns`, TCP 53 as `domain`, UDP 123 as `ntp`; 22, 123 over TCP, and 443 stay numbers. A range from 0 prints as `lt`, one up to 65535 as `gt`, a range of one port as `eq`, and `range 0 65535` not at all.
    - An IPv4 rule prints protocols 1, 2, 4, 47, and 89 as `icmp`, `igmp`, `ipinip`, `gre`, and `ospf`; 50, 51, and 112 stay numbers. An ACL6 prints 50 and 51 as `ipv6-esp` and `ipv6-ah`, 58 as `icmpv6`, 0 as `ipv6`, and its addresses in capitals, `/128` kept.
    - A rule whose match repeats another rule's is refused: `The rule already exists`. A rule's description is `rule <n> description <text>`, printed after the rule, and undone with `undo rule <n> description`. `undo rule <n>` takes the description with it.
    - `traffic-filter acl <name> inbound` is taken in a VLAN interface's view and in a VLAN's view too, in a candidate. What it checks there was not tested.
    - `cpu-defend policy` has `blacklist <id> acl <n>`, but no `filter`: `Unrecognized command`. Huawei's reference does not say what a blacklist does with a `deny` rule.
- DHCP server (V200R005C00SPC800, pools committed with `commit trial`, the next plan empty but for `dhcp enable`, which went into a candidate only):
    - A VLAN interface takes no `dhcp select global`, `dhcp select interface`, or `dhcp server enable`, and the system view no `dhcp server request-packet all-interface`: each is `Unrecognized command`. Nothing ties a pool to an interface.
    - An `ip pool` commits without `dhcp enable`. It prints `vpn-instance` first, then `gateway-list`, `network`, `static-bind` by address, `excluded-ip-address`, `lease`, and `dns-list`. `gateway-list` and `dns-list` end with a space. A one-address exclusion prints as the address alone, and a lease of one day, the default, not at all.
    - An exclusion over the gateway is refused, `The IP address has been configured as a gateway address`, and a static binding of an excluded address, `The IP address has been configured as an excluded address`.
    - A gateway changes only once the network is gone: `Please delete all sections of the pool before modifying the gateway IP address`. `undo network` and `undo ip pool` ask `[Y/N]`, as does `vpn-instance` in a pool that has a network. Circuit removes a pool whose gateway or network changes, and writes it again.
    - `dhcpv6 pool <name>` refuses a name with a `-` (`Wrong parameter`), and takes `ctest_pool6`.
- OSPF (V200R005C00SPC800, on VLAN interfaces of new VLANs with no ports, committed with `commit trial`, the next plan empty, then rolled back):
    - `ospf dr-priority 1`, the default, is not printed. `undo ospf dr-priority` and `undo ospf network-type` take no value; with one, `Too many parameters`.
    - A range prints as sent: `abr-summary <address> <mask>`, then `not-advertise` or `cost <n>`, from 0 to 16777214. It is undone by its address and mask alone.
    - An NBMA link's neighbors are the process's `peer <address>` lines. `p2mp-peer` and `ospf p2mp-peer` are `Unrecognized command` in a VLAN interface's view.
    - A virtual link is `vlink-peer <router ID>` in the view of the area it crosses, printed as sent, with no timers.
    - On an NBMA or point-to-multipoint link, `display ospf interface` shows hello 30 s and dead 120 s when none is set, and a broadcast link 10 s and 40 s.
    - `undo ospf 1 router-id <id>` is `Too many parameters`. The process goes with `undo ospf 1`, which asks `[Y/N]`.
    - Each passive interface is a line of its own, `silent-interface Vlanif<n>`, printed after `import-route direct` or `static`, and undone by its own line: a new one leaves the old in place.
- IS-IS (V200R005C00SPC800, a process with no interface committed with `commit trial`, the next plan empty, then rolled back):
    - `import-route isis level-2 into level-1 filter-policy route-policy <name>`, and its `ipv6` twin, are refused while the route-policy does not exist: `The specified route-policy does not exist`. Circuit writes route-policies before IS-IS.
    - The process prints its IPv6 lines after its others, between two indented ` #` lines, which the read skips. `is-level level-1-2`, the default, is not printed. `ipv6 enable` without a topology is IPv6's own topology; `topology standard` shares IPv4's.
    - `cost-style` and `is-level` answer `IS-IS process 1 will be reset`. `set-overload` asks `Continue? [Y/N]`, and `undo isis 1` asks before it deletes the process.
    - A second `network-entity` adds an area address beside the first, so a new NET is sent before the old one is undone. That, a leak's new policy and topology sent over the old, and the removal went into a candidate during a trial, and were cleared.
- IS-IS on VLAN interfaces (V200R005C00SPC800, on new VLANs with no ports, committed with `commit trial`, the next plan empty, then rolled back):
    - A VLAN interface refuses `ipv6 address` with `IPv6 has not been enabled`, and `isis ipv6 enable 1` with `Please enable IPv6 on this interface first`, until `ipv6 enable` is sent there. It prints its IPv6 address in capitals.
    - Level 1's key is the process's `area-authentication-mode`, and level 2's `domain-authentication-mode`, each `md5 cipher <key>` or `hmac-sha256 key-id <id> cipher <key>`, with key IDs 0 to 65535 taken. `hmac-sha1` is `Unrecognized command`. `md5` warns `The algorithm is not safe` and is taken.
    - A hello's key is `isis authentication-mode ...` on the interface, with `level-1` or `level-2` after it, or neither for both. On a point-to-point link, a level is `Too many parameters`: its one hello takes one key.
    - Each key prints as a cipher, `cipher %^%#...%^%#`, before `level-1` or `level-2`. A new key is taken over the old. A hello's key is undone by its level, `undo isis authentication-mode level-1`, or with nothing after it; a level's by `undo area-authentication-mode` or `undo domain-authentication-mode`.
    - `isis bfd enable` and `isis bfd min-tx-interval ... detect-multiplier ...` print as sent, and need `bfd` in the system view. `undo bfd` asks `The BFD process will be deleted. Continue? [Y/N]`, and a candidate took it before the VLAN interface's `undo isis bfd` lines.
    - `isis silent` prints with a space after it, and `isis ipv6 cost` before `isis cost`.
- Marking with MQC (V200R005C00SPC800, classifiers, behaviors, and policies committed with `commit trial` on spare port 10GE1/0/48, then rolled back):
    - One traffic policy refuses a classifier with an IPv4 ACL beside one with an IPv6 ACL: `If-match IPv6 ACL in traffic classifier ... and if-match IPv4 ACL in traffic classifier ... cannot be configured in one traffic policy`. A port took one policy for each family inbound, and `display traffic-policy applied-record` showed both `success`.
    - `remark dscp` prints a value by the name it has: 46 as `ef`, 0 as `default`; 44 stays a number. Behaviors print in the order of their names. `if-match dscp`, `if-match ipv6 acl`, and a port's `traffic-policy` print with a space after them.
    - A policy still applied, or a behavior or classifier still in a policy, is refused at once: `The traffic policy has been used`. Unlike an ACL, its removal is taken once the same candidate lets go of it (in a candidate, cleared). Circuit unbinds the policies first.
    - Classifiers print in the order of their names. `if-match dscp 0` prints as `default`, and `if-match ipv6 dscp 1` as a number.
    - `display current-configuration configuration traffic-policy` is `Wrong parameter`.
- Marking with MQC sets a packet's queue with `remark local-precedence <service class>` in a behavior, printed with two spaces after it; `remark service-class` is `Unrecognized command`. A behavior named with 42 characters was `Wrong parameter`; 24 were taken (V200R005C00SPC800, committed with `commit trial`).
- Classes and schedulers (V200R005C00SPC800, committed with `commit trial` on spare port 10GE1/0/48, the next plan empty but for the owner's ports, then rolled back):
    - A port's defaults print nothing, and `display qos configuration interface <port>` shows them: it trusts the outer 802.1p (`trust 8021p outer`; `trust 8021p` alone is `Incomplete command`) through `diffserv domain default`, writes the 802.1p of what it sends from its queue (`phb marking 8021p : enable`), keeps the DSCP, and sends all 8 queues by PQ, the highest first. `display diffserv domain` shows each domain's whole mapping.
    - A new domain starts with the default domain's mapping, and prints only the lines that differ from it, with their color. A new `ip-dscp-inbound <n> ...` or `8021p-inbound <n> ...` is taken over the old one. Each is undone by its number alone, `undo ip-dscp-inbound 38`; with its class and color, `Too many parameters`.
    - A domain a port trusts is refused at once, `The DiffServ domain cannot be deleted, because it has been used`, and taken once the same candidate's port has let go of it.
    - A port takes `trust upstream <domain>`, `trust dscp`, and `qos phb marking 8021p disable`, undone by `undo trust upstream`, `undo trust`, and `undo qos phb marking 8021p disable`. `undo trust upstream <domain>` and `undo trust dscp` are `Too many parameters`. `qos phb marking 8021p enable` is `Unrecognized command`.
    - `qos drr 0 to 1 3 to 4` prints as sent, and `undo qos drr <list>` takes the weights of its queues with it. A weight before its queue is in DRR is refused: `Please change the schedule mode of the queue first`. Weights are 1 to 100, and 1, the default, is not printed. `undo qos queue <n> drr weight` takes no value. There is no WFQ: `qos wfq` is `Unrecognized command`.
    - `qos queue <n> shaping cir 20000 pir 20000` prints with `kbps` after each rate and a space at the end. A lower rate is refused: `CIR value must be between 64 kbps and 100 gbps`. It is undone by `undo qos queue <n> shaping`; with its rates, `Too many parameters`.
    - `qos lr cir 95000 outbound` prints as `qos lr cir 95000 kbps outbound`, and the switch picks a CBS of 760000.
    - A burst prints with its unit too: `qos lr cir 100000 cbs 125000 outbound` as `qos lr cir 100000 kbps cbs 125000 bytes outbound`, and a CAR profile `qos car <name> cir 200000 cbs 250000` as `cir 200000 kbps cbs 250000 bytes`. A profile without a burst prints as `cir 200000 kbps`, with no CBS. Both are taken as printed. A port prints `qos lr` before `qos car inbound`.
    - A CAR profile a port uses can't be removed: `The QoS CAR template cannot be deleted, because it has been used`. A new profile of the same name sent over it replaces it whole, its burst too, and so does a new `qos lr` (in a candidate).
    - A queue has no depth: `qos queue <n> length` and `qos queue <n> buffer` are `Unrecognized command`. `drop-profile <name>` with `color green low-limit 20 high-limit 50 discard-percentage 100`, and `qos queue <n> wred <name>` on a port, went into a candidate.
    - There is no rate for each address: `qos car inbound source-ip-address range ... per-address cir ...` is `Unrecognized command` in the system and VLAN views and `Too many parameters` in a port's, and `ip car` is `Unrecognized command`. A behavior's `car` takes `share`, one rate for every port it is on.
