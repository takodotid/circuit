# Decisions

These decisions are binding. A change to one is a new decision with the next number. A missing number was replaced, moved to `AGENTS.md`, or dropped.

## The language

- **1.** Circuit v1's config is declarative TypeScript.
- **2.** Circuit is primitive: devices only. Tenants and upstreams are the project's own. A project may build them with its own function in `lib/`.
- **4.** A device's groups follow [the model](docs/reference/model.md). Winbox is a reference, not the target.
- **5.** Ordered rules are arrays, with no numbers. Another file's rules are placed with `merge`.
- **6.** `merge([...])` flattens, and makes a list or a map by the field it lands in.
- **7.** A match field may take a list. Interface sets exist.
- **8.** The core is `circuit()` (the network) and its `.device()`, `merge`, `literal`, `secret`, and `part(kind, value)` for parts.
- **10.** Ready-made rules are data in `presets`, not functions.
- **11.** `checks` takes Circuit's checks (on, or with settings) and the project's own functions.
- **13.** A rule's description is optional and short. One description for a rule with a list is fine.
- **14.** The sessions of one upstream share a `neighbor_group`, even where that adds a template on the device.
- **17.** Field names say what they are ([the renames](docs/reference/model.md#from-circuit-0x)).
- **22.** The trust boundary check is Circuit's `untrusted_vlans`, with `filtering_devices` and `mixed_links`.
- **25.** Data is snake_case: every field, every preset, and every variable of a project. Functions are camelCase. Presets are one `presets` object. (Includes 59.)
- **26.** Circuit's functions and `presets` are globals: a project's files don't import `"circuit"`. Circuit v1 is a binary. It writes the editor types into a project's `.circuit/types`.
- **33.** An export toward an iBGP neighbor that doesn't write `keep_ours` stops Circuit.
- **35.** A static route's `prefix` stays one prefix, not a list.
- **37.** The community scheme is data in `circuit()`, not a function value.
- **38.** `circuit({...})` in `circuit.ts` returns a network value; devices are `<network>.device({...})`, typed from that network. Circuit finds the device files itself, with no extra command. One project may hold several networks.
- **40.** A static route drops traffic with `blackhole: true`.
- **41.** Route policy rules are plain objects, the condition first: `{ if, set, then }` or `{ call }`.
- **42.** A link is written at both ends, each in its device's file: each device is its own source of truth.
- **43.** A built-in check, `same_vlan_ids`: one VLAN name has one ID on every device of a network.
- **51.** Every rule kind (route policy, filter, NAT, ACL) is `{ if, then }`.
- **52.** `interfaces.vlan_interface`, not `interfaces.vlan`, so "vlan" means a VLAN only.
- **53.** Route policy names are lowercase kebab-case, like every other name.
- **54.** A network value is named after its AS, such as `as64500`: the suggested convention.
- **55.** Nothing is filled in, anywhere. A linked port's description is written by hand: Circuit may warn, never fill it in. Circuit writes no defaults back.
- **56.** A site's addresses carry their length where an interface needs one. No template strings in a project's files.
- **57.** `management.allow` takes a list of prefixes or the name of an address set, with completion.
- **58.** `connection.host` stays apart from any interface's address.
- **62.** Circuit ships address helpers (`address.contains`, `.overlaps`, and the rest) for a project's own checks.
- **63.** A finding of a project's own check may name its device and path, so Circuit points at the line.
- **65.** A project's own checks read the network resolved, as the devices run it. The project doesn't change.
- **66.** A network's prefixes live in `circuit({ prefixes })`, for devices, checks, and integrations.
- **72.** `merge` is decided by the field it lands in, in the editor too, and names complete inside it.
- **87.** A later Circuit reads YAML projects too: one `!ref` tag, and v1's TypeScript as the schema ([#167](https://github.com/takodotid/circuit/issues/167)).
- **90.** Project files import each other by relative path. The `circuit` path alias in `tsconfig.json` is for `import type` only, because the binary doesn't read `tsconfig.json`.
- **116.** A static route's `next_hop` is a plain address, and its interface goes in `interface`, never after `%`. A platform that can't write both refuses them.
- **117.** The docs show part of an example with a VitePress region include.
- **119.** RouterOS writes a next hop with its interface as `gateway=<next_hop>%<interface>`, tested on a CCR2216 with RouterOS 7.24.6.
- **120.** A BGP neighbor or neighbor group turns on GTSM (RFC 5082) with `ttl_security: true`, never with `multihop` ([#216](https://github.com/takodotid/circuit/issues/216)).
- **121.** A route reflector marks each iBGP client with `route_reflector_client: true` on its neighbor or neighbor group, and states its cluster ID in `routing.bgp.cluster_id`. Circuit fills in no cluster ID ([#213](https://github.com/takodotid/circuit/issues/213)).
- **122.** A BGP neighbor or neighbor group gets a default route with `send_default_route: true` (OpenConfig `send-default-route`), whatever its export policy says. `routing.bgp.aggregates` lists `{ prefix, summary_only }` (OpenConfig local aggregates): an aggregate stands for the more specific routes BGP holds, and the export policy decides who gets it. RouterOS has no aggregates and refuses them ([#217](https://github.com/takodotid/circuit/issues/217)).
- **123.** A BGP neighbor or neighbor group turns on graceful restart (RFC 4724) with `graceful_restart: true`. `max_prefixes` takes a number, which keeps the session closed, `{ limit, restart_after }` in seconds, or `{ limit, warn_only: true }`, never both ([#216](https://github.com/takodotid/circuit/issues/216)).
- **124.** A route policy has no AS path regular expression. It matches `first_as` (the neighbor that sent the route), `origin_as` (RFC 6811), and `as_path_contains`, each an AS number, a range `{ min, max }`, or a list of these, as `Ports` is, and `as_path_length`. Each platform writes them its own way. `standard_community` and `large_community` take a list, any of which matches, and `*` for any value of a part. `presets.bogon_asns` is the NLNOG BGP Filter Guide's list, and stays out of `presets.bgp_sanity` ([#217](https://github.com/takodotid/circuit/issues/217)).
- **125.** A routed interface checks sources with `urpf: { ipv4, ipv6 }`, each `"strict"` or `"loose"` (RFC 3704, OpenConfig `urpf/mode`). Without it, the device keeps its own default. Source-based RTBH (RFC 5635) is a blackhole route with uRPF on, with no field of its own. A platform with one setting for many interfaces writes it only when all of them agree ([#218](https://github.com/takodotid/circuit/issues/218)).
- **126.** `system.aaa` checks logins with TACACS+ (RFC 8907) or RADIUS (RFC 2865, RFC 2866) servers, with OpenConfig's names: `tacacs` or `radius`, each server `{ address, secret_key, source_address }`, RADIUS also `auth_port` and `acct_port`, then `remote_role` and `accounting_events` (`login`, `command`). A name in `system.users` logs in on the device first; any other is checked with the servers, in order. Every user a server accepts gets `remote_role`. Accounting goes to the same servers. There is no `timeout`, since FortiOS has none per TACACS+ server ([#214](https://github.com/takodotid/circuit/issues/214)).
- **127.** An OSPF area is a stub area or an NSSA with `type`, totally so with `no_summaries`, and states the cost of its border router's default route in `stub_default_cost`: Circuit fills in none, and `validate` warns without it. An OSPF interface has `hello_interval` and `dead_interval` in seconds, and `authentication: { algorithm, key_id, key }`, `md5` or HMAC-SHA (RFC 5709), for OSPFv2 only ([#224](https://github.com/takodotid/circuit/issues/224)).
- **129.** `ipv6_ra` takes `true` or what the advertisements say (RFC 4861), with OpenConfig's names: `interval`, `lifetime`, `prefixes`, each `{ prefix, valid_lifetime, preferred_lifetime, disable_autoconfiguration }`, and RFC 8106's `dns_servers` and `dns_search_list`. Without `prefixes`, it announces each IPv6 network of the interface. A value left out is the device's own. A platform that needs the least interval beside the most gets a third of it, as RFC 4861 sets ([#221](https://github.com/takodotid/circuit/issues/221)).
- **130.** A router in a BGP confederation (RFC 5065) writes its member AS in `routing.bgp.asn` and `routing.bgp.confederation: { identifier, member_as }`, OpenConfig's names. `member_as` lists the other member ASes only, and a neighbor whose `remote_as` is one of them is in the confederation, as OpenConfig infers it. Circuit refuses it on RouterOS, since 7.24 shows the identifier to neighbors inside the confederation ([#213](https://github.com/takodotid/circuit/issues/213)).
- **131.** A port is guarded with `stp.bpdu_guard` and `stp.guard: "root"`, OpenConfig's names. `switching.dhcp_snooping` and `switching.ra_guard` (RFC 6105) cover every switched port of the device, and only a port with `dhcp_trusted` or `ra_trusted` takes DHCP offers or router advertisements. DHCPv6 snooping, dynamic ARP inspection, QinQ, and private VLANs wait for later ([#220](https://github.com/takodotid/circuit/issues/220)).
- **132.** `monitoring.snmp.traps` lists trap receivers (RFC 3416), each `{ address, port }` with a `community` for version 2c or a `user` of `snmp.users` for version 3. Each gets every trap the platform sends. RouterOS and FortiOS send traps only, so there are no informs. A syslog collector sends over TLS (RFC 5425) with `transport_security: { ca_certificate }`, OpenConfig's name, the CA one of `system.certificates`. `flow_export` takes RFC 6728's `active_timeout` and `idle_timeout` in seconds, which only NetFlow v9 and IPFIX have. Active probes wait, as the platforms' probes share no shape ([#225](https://github.com/takodotid/circuit/issues/225)).
- **133.** `services.dhcpv6_server` is a DHCPv6 server (RFC 8415) per interface: `pool`, the first and last address given (IA_NA), in a network of the interface; `prefix_delegation: { pool, prefix_length }` (IA_PD); `dns`; and `lease_time`. With neither pool, it gives only `dns` (stateless). `ipv6_ra` sets the M and O flags with OpenConfig's `managed` and `other_config`, never filled in: `validate` warns when they don't send hosts to the server. `dhcp_server` is IPv4 only. OpenConfig has no DHCP server model ([#221](https://github.com/takodotid/circuit/issues/221)).
- **134.** `switching.arp_inspection` is dynamic ARP inspection on every switched port of the device. It checks ARP against what `dhcp_snooping` saw, so it needs it. A port with `dhcp_trusted` passes ARP unchecked, as on Junos. There are no static bindings: a host whose address is written by hand needs a trusted port ([#220](https://github.com/takodotid/circuit/issues/220)).
- **135.** A private VLAN (RFC 5517) is written on each of its secondary VLANs in `switching.vlans`, as `private_vlan: { primary, type }`. Its `type` is `isolated` or `community`. A port is isolated or in a community by its access VLAN. It is promiscuous in the primary VLAN, as an access port, a trunk, or the VLAN interface. A secondary VLAN holds access ports only, so no trunk carries a private VLAN between switches. RouterOS keeps isolated ports apart with a split horizon, and has no communities ([#220](https://github.com/takodotid/circuit/issues/220)).
- **136.** A QinQ port is a port or LAG with `qinq_vlan`: every frame that arrives takes that VLAN's tag on top, and trunks carry the VLAN as any other. The outer tag is 0x8100, which a QFX5100 on Junos 21.4 can't change, not IEEE 802.1ad's 0x88a8. DHCP snooping, ARP inspection, and RA guard don't look inside a QinQ VLAN, and no VLAN interface is on one. There is no selective QinQ, VLAN translation, or QinQ VLAN interface ([#220](https://github.com/takodotid/circuit/issues/220)).
- **137.** `routing.isis` is IS-IS (ISO/IEC 10589, RFC 1195) with OpenConfig's names: one `net`, `level_capability` (`level-1`, `level-2`, or `level-1-2`), `address_families` in one topology (RFC 5308), and `interfaces`, each with `metric`, `passive`, and `network` as OSPF's. Each is written out, and the metrics are always wide (RFC 5305). There is no authentication, since RouterOS 7.24 has none. Route leaking between levels, the overload bit, multi-topology, and BFD wait ([#224](https://github.com/takodotid/circuit/issues/224)).
- **138.** A BGP neighbor or neighbor group runs in a VRF with `vrf`, as an interface or a static route names its VRF (OpenConfig's interface `network-instance`), not in a BGP block per VRF. Its session learns into the VRF, and announces only what the VRF holds, `originated_prefixes` too. FortiOS 6.2 has no VRF for BGP and refuses it ([#219](https://github.com/takodotid/circuit/issues/219)).
- **139.** `routing.vrf_imports` lists `{ from, to, policy }`: the routes a VRF, or the main table as `main`, takes from another, through a route policy. It is OpenConfig's inter-instance import policy, without route targets, and one import per pair of tables. RouterOS hands the routes over through BGP's VPN table, between VRFs only, with route targets Circuit numbers by each import's place. FortiOS 6.2 has no route leaking between VRFs and refuses it ([#219](https://github.com/takodotid/circuit/issues/219)).
- **140.** IS-IS signs every packet it sends, hellos too, with HMAC-MD5 (RFC 5304), which replaces decision 137's "no authentication". `routing.isis.authentication: { key }` signs every level the device runs, and `routing.isis.levels`, OpenConfig's levels, holds a key per level instead: one or the other. There is no HMAC-SHA (RFC 5310) and no hello key per interface yet. FortiOS takes an MD5 key from a key chain only, so Circuit writes one per level, `circuit-isis-l1` and `circuit-isis-l2`. RouterOS 7.24 has no IS-IS authentication and refuses it ([#224](https://github.com/takodotid/circuit/issues/224)).
- **141.** `routing.isis.overload_bit` sets the overload bit (ISO/IEC 10589), OpenConfig's `lsp-bit/overload-bit/set-bit`. An IS-IS interface's `bfd` runs BFD for each family IS-IS routes, with `routing.bfd`'s timers, as OSPF's does. There is no overload bit for a while after a restart (RFC 3277) and no BFD TLV (RFC 6213). RouterOS 7.24 has neither and refuses both, and FortiOS 6.2 refuses BFD ([#224](https://github.com/takodotid/circuit/issues/224)).
- **142.** OSPF runs in a VRF with `routing.ospf.vrf`, as a BGP neighbor names its VRF (138). Every OSPF interface routes in that VRF, and OSPF uses the device's router ID there. A device runs one OSPF, so OSPF in the main table and in a VRF at once waits. FortiOS 6.2 has no VRF for OSPF and refuses it ([#219](https://github.com/takodotid/circuit/issues/219)).
- **143.** A service of the device itself names its VRF with `vrf` where it is written, as 138 does. Each management service and `monitoring.snmp` answer in it. `system.ntp`, `system.dns`, a syslog collector, and a RADIUS server are reached through it, as OpenConfig gives a server its `network-instance`. A DHCP server serves in the VRF of its interface. TACACS+ servers, flow collectors, and the NTP and DNS servers the device runs stay in the main table for now. Junos has no VRF for SSH and its other services, and reaches a resolver only through `mgmt_junos`. FortiOS 6.2 has no VRF for any of them. Each refuses what it lacks ([#219](https://github.com/takodotid/circuit/issues/219)).
- **144.** `services.pppoe_server` is a PPPoE server for subscribers (RFC 2516) on its `interfaces`, with `service_name`, `local_address`, `mtu`, and a `pool` and `dns` as `dhcp_server` writes them. Its `radius` servers, as `system.aaa.radius` writes them, check each subscriber (RFC 2865) and get its accounting (RFC 2866), every `acct_interim_interval` seconds too (RFC 2869). `dynamic_authorization` lets them end or change a session (RFC 5176). Subscribers and their rates live in RADIUS: Circuit writes no local user or rate, and removes those it finds. A platform with one RADIUS setting for PPP writes it only when all its PPPoE servers agree, as 125 does for uRPF. IPv6 prefix delegation over PPP, IPoE, and session interface sets wait ([#226](https://github.com/takodotid/circuit/issues/226)).

- **145.** A port, a LAG, or a VLAN interface limits its traffic with `rate_limit`: `input` is what arrives, and `output` what leaves. Each is a rate, which leaves the burst to the device, or `{ cir, bc }`, RFC 2697's committed rate and burst in bytes, with OpenConfig's names. An ACL rule's `rate` takes the same. Junos's policer needs a burst, so Junos refuses a rate without one there, and a platform with no place for a burst refuses `bc`. RouterOS limits with a simple queue, which traffic on a bridge port, on the fast path, or offloaded skips, so Circuit refuses it there. FortiOS 6.2 uses shared shapers and shaping policies, as NP6 offload ignores `inbandwidth`. VRP is experimental and Raisecom ROS refuses it. `shaping` beside `rate_limit.output` is refused. Classification, marking, and queues wait ([#215](https://github.com/takodotid/circuit/issues/215)).
- **146.** `routing.mpls.ldp` runs MPLS (RFC 3031) with labels from LDP (RFC 5036) in the main table, with OpenConfig's names: `lsr_id` and `interfaces`, the ports and interfaces that forward MPLS and run LDP. The LSR ID is the address of a loopback that OSPF or IS-IS announces, and LDP sessions run between LSR IDs. Junos takes it from `routing.router_id`, so there the two are one address. Junos is experimental: the QFX5100 took the statements in `commit check`, but has no license to run them. Targeted LDP, label filters, RSVP-TE, segment routing, and VPNs come later. FortiOS has no MPLS, and VRP and Raisecom ROS refuse it until it is built ([#222](https://github.com/takodotid/circuit/issues/222)).
- **147.** A source `snat` shares a pool among subscribers with `to_pool` and `port_set_size` (RFC 8512's external address pool and `port-set-size`), RFC 7422's deterministic mapping. Each address of `if.src`, one IPv4 prefix, always leaves as the same pool address with the same block of ports. Each pool address takes the same number of subscribers, and the blocks go in address order from port 1024. Other protocols leave as the same address. RouterOS writes MikroTik's way: a jump chain for each pool address, with a source NAT rule for TCP and one for UDP per subscriber. There, more subscribers than a /20, the largest proven, is a warning. FortiOS refuses it, since its fixed port range pool can move a session out of its block. Port block allocation with logs, NAT64, and a lookup command come later ([#227](https://github.com/takodotid/circuit/issues/227)).
- **148.** `interfaces.ipsec` is a route-based IPsec tunnel (RFC 4301), an interface as `gre` is, so BGP or OSPF runs over it. It authenticates with `pre_shared_key` over IKEv2 (RFC 7296) only, since RFC 9395 deprecates IKEv1. `ike` and `esp` write out every algorithm by its IANA name. They take the ones RFC 8247 and RFC 8221 rate MUST or SHOULD, so AES-CBC with `integrity` or AES-GCM without, and Diffie-Hellman groups by number. `esp.pfs_group` left out means no PFS. `presets.ipsec_rfc8247` holds the IKE algorithms RFC 8247 makes mandatory. A tunnel has no `vrf` or `mtu` yet. Certificates and remote access come later. RouterOS refuses it, since its XFRM interfaces, new in 7.25, cut a router off in a test. Switches that don't encrypt what they forward refuse it too ([#223](https://github.com/takodotid/circuit/issues/223)).
- **151.** An L3VPN (RFC 4364) is a VRF with `route_distinguisher` and `route_targets: { import, export }`, OpenConfig's network instance `route-distinguisher` and import and export route targets, and BGP neighbors with `vpnv4` or `vpnv6` (RFC 4659) in `address_families`. A VRF sends every route it holds with its export targets, connected, static, or learned from its OSPF or BGP, and takes the VPN routes that carry an import target; per-VRF policies wait. Route targets pick VPN routes, so a neighbor's `import_policy` and `export_policy` apply to its `ipv4` and `ipv6` routes only. `validate` checks the forms of RFC 4364, RFC 4360, and RFC 5668, one route distinguisher per VRF, and that a VPN session is iBGP, in the main table, from `routing.mpls.ldp.lsr_id`: inter-AS VPNs wait. RouterOS writes a `/routing bgp vpn` entry per VRF, proven on RouterOS CHR in CI, and refuses `vpnv6`, whose routes it kept unreachable, `vrf_imports` beside an L3VPN, and a prefix limit on a VPN session. Junos refuses it while its MPLS is experimental, FortiOS has no MPLS, and VRP and Raisecom ROS don't build it ([#222](https://github.com/takodotid/circuit/issues/222)).
- **152.** `interfaces.pseudowire` is an Ethernet pseudowire (RFC 4448) to another PE, which LDP sets up with the PWid FEC (RFC 8077): `peer`, the far PE's LSR ID, and `pw_id`, OpenConfig's `remote-system` and `virtual-circuit-identifier`. It is a port in its `access_vlan`, and its frames cross without the VLAN's tag, raw mode. A pseudowire and a customer's port in one VLAN make a VPWS, and several pseudowires in one VLAN an LDP-signaled VPLS (RFC 4762): every pseudowire is in one split horizon, so a frame from one never leaves by another. `validate` wants `routing.mpls`, an IPv4 `peer` that is not the router's own LSR ID, one `pw_id` per peer, and a pseudowire back with the same `pw_id` when the peer is in the project. RouterOS writes a VPLS interface with `cisco-static-id`, MikroTik's PWid FEC, and a bridge port with its own horizon, proven on RouterOS CHR in CI. A running pseudowire lowers each VLAN interface on its bridge to MTU 1496, so RouterOS wants `mtu` of 1496 or less on each beside a pseudowire, rather than Circuit lowering it unseen. Junos refuses it while its MPLS is experimental, FortiOS has no MPLS, and VRP and Raisecom ROS don't build it. A pseudowire with `qinq_vlan` or tagged VLANs, an MTU of its own, the control word, BGP-signaled VPLS, and a pseudowire in a private VLAN wait ([#222](https://github.com/takodotid/circuit/issues/222)).
- **153.** An IPsec tunnel's `liveness_check: { interval, retries }` is IKEv2's liveness check (RFC 7296 §2.4), also called dead peer detection. Left out, the device checks as it does by default. `nat_traversal: "always"` puts ESP in UDP (RFC 3948) even with no NAT. Left out, ESP goes in UDP only when IKE finds a NAT (RFC 7296 §2.23). The NAT keepalive interval is the device's own. Instead of `pre_shared_key`, a tunnel takes `certificate`, one of `system.certificates` with its key, and `ca_certificate`, the CA that signed the peer's, as a syslog collector's `transport_security` writes it. Any certificate that CA signed is taken: matching the peer's name, revocation lists, and OCSP come later. Both ends authenticate the same way. FortiOS checks a silent peer with `dpd on-idle`, and takes only a certificate that CA signed, through a `user peer` named after the CA. Policy-based tunnels, IKEv1, remote access, and RouterOS wait ([#223](https://github.com/takodotid/circuit/issues/223)).
- **154.** `interfaces.pppoe_client` is a PPPoE client (RFC 2516), an interface as `gre` is, so a static route, a NAT rule, or a filter rule points to it. It runs over a routed port, a LAG, or a VLAN interface, its `interface`, and logs in with `user` and `password`, with `service_name` and `mtu` when written. The server gives its IPv4 address (IPCP, RFC 1332), so it has no `addresses`. It adds no default route: a static route with `interface` is one. It uses `system.dns`, not the server's resolvers, as `dhcp_client` does. It has no `vrf` yet. FortiOS has a PPPoE client, but refuses it until one is tested. The switches of Junos, VRP, and Raisecom ROS have none ([#226](https://github.com/takodotid/circuit/issues/226)).
- **155.** IPv6 over PPPoE is a prefix delegated by DHCPv6 (RFC 9915) over the session (IPv6CP, RFC 5072), with decision 133's names, which replaces that part of decision 144's "wait". `services.pppoe_server.prefix_delegation` is `dhcpv6_server`'s `{ pool, prefix_length }`. `interfaces.pppoe_client.prefix_delegation.interfaces` asks for a prefix, and gives each interface listed there a /64 of it, as RFC 7084 has a home router do. The router's address there is written by its last 64 bits, such as `{ home: "::1" }`, since nothing is filled in. A prefix hint, a prefix RADIUS sends (RFC 4818), and a prefix for the session itself (SLAAC over PPP) are not built or tested yet. IPoE and session interface sets still wait ([#226](https://github.com/takodotid/circuit/issues/226)).
- **156.** A field may say what a device does and can't stop doing. Raisecom ROS answers time queries whenever it takes time from servers, and has no setting to stop it, so there `services.ntp_server` writes nothing, and `system.ntp` without it is a warning, never filled in (55). Raisecom ROS limits ports and LAGs with `rate_limit` (145): a rate alone takes the switch's own burst, one second at the rate and at most 4096 kB, and `bc` is in whole kB of 1000 bytes. Its BPDU guard is one setting for the whole switch, and the switch finds edge ports by itself, so with `bpdu_guard` each port that runs spanning tree writes `edge` ([#215](https://github.com/takodotid/circuit/issues/215)).
- **158.** Every pool writes `port_allocation`, how each subscriber gets its ports. `deterministic` is 147's mapping. `dynamic` is RFC 8512's port range allocation: the device gives a subscriber a block of `port_set_size` ports when it needs one, up to `port_sets_per_subscriber` blocks (RFC 6888 REQ-4), and takes it back once the block's last connection ends. Its `if.src` may be any match. Only the device's log of each block finds a subscriber, so `circuit nat lookup` points there, and a platform warns when no syslog collector takes that log. FortiOS writes a `port-block-allocation` pool named after its prefix, proven on a FG-3700D on 6.2.2, and logs each block given and taken back at notice. FortiOS still refuses a deterministic pool: Fortinet's fixed port range algorithm, checked again, moves a session out of its share once the share is full. RouterOS refuses a dynamic pool, as it has no port block allocation. A deterministic pool's config is its record (RFC 7422), so Circuit logs no translation. A block's idle timeout, logs while a block is held, NAT64, and DNS64 wait ([#227](https://github.com/takodotid/circuit/issues/227)).
- **159.** `qos.marking` marks the packets a device routes, RFC 2475's classifier and marker, as an ordered list of `{ if, then }` rules: the first rule that matches marks a packet, and a packet that no rule matches keeps its DSCP. - **193.** A queue's depth and RED, which decision 172 left waiting. A scheduler's queue takes `depth_packets`, the most packets it holds, OpenConfig's `max-queue-depth-packets`. What comes while it is full is dropped: tail drop. Without it, the queue keeps the platform's depth. `red` drops packets at random before the queue is full (RFC 2309, RFC 7567), with the names of OpenConfig's `red`: `min_threshold_percent` and `max_threshold_percent`, whole percents of `depth_packets`, which `red` needs. RouterOS writes a queue type for each queue with a depth, named as its queue tree leaf: `pfifo` with `pfifo-limit`, or `red`. RouterOS's RED counts bytes, each threshold times `red-avg-packet`, so Circuit writes 1500, the most an Ethernet frame carries. The thresholds are rounded down to whole packets. `red-burst`, which RouterOS wants at least the lower threshold, is the lower threshold twice and the upper one once, over 3, as Linux's tc-red manual advises. A DiffServ domain named `circuit` puts each DSCP, or each PCP, into its class's queue where that differs from the switch's own mapping, and keeps the color of each DSCP. Every port trusts it, with `trust dscp` when a class other than the default lists a DSCP, and keeps the PCP a packet arrives with, `qos phb marking 8021p disable`, which the switch otherwise writes from the queue. A port trusts the DSCP or the PCP, not one and then the other as decision 196 orders them, so VRP refuses classes that list both. A scheduler is on a port: its strict queue is PQ, shaped to its `max` with `qos queue <n> shaping`, its weighted queues are DRR with each `share` as a weight, and its `rate` is `qos lr`. The switch sends its strict queues in order, the highest first, where decision 172's take turns, so VRP refuses a second strict queue. A port without a scheduler keeps the switch's own, every queue by PQ. A marking rule's `class` is `remark local-precedence` in a behavior of its own, named after the rule, and a rule that writes a DSCP also sets the queue of the class of that DSCP, since the switch sorted the packet by the DSCP it arrived with. VRP refuses a scheduler on a LAG or a VLAN interface, and classes beside a LAG, as no Eth-Trunk has taken the trust settings. It refuses decision 193's `depth_packets`, and so `red`: V200R005 sets no depth for a queue. It refuses decision 195's `rate_limit.per_prefix`: the CE6855 has no CAR for each address. A CE6855 on V200R005 committed classes by DSCP and by PCP, a scheduler, and marking rules with a class with `commit trial` on a spare port with no optic. The plan after it was empty but for the owner's ports, which the test left alone, and the marking policy, applied to that port in place of the whole switch. A change and the removal went into a candidate, and the plan against `display configuration candidate merge` was the same. No packet crossed the port, so they are experimental, as decision 174 has it for marking ([#351](https://github.com/takodotid/circuit/issues/351)).
- **231.** This replaces decision 202's "VRP refuses EVPN". VRP writes decision 201's EVPN over VXLAN as Huawei documents it on CloudEngine switches. It writes `evpn-overlay enable`, and a bridge domain for each segment, numbered by its VNI, with `l2 binding vlan` for its VLAN, `vxlan vni`, and an `evpn` view with the segment's `route-distinguisher` and a `vpn-target` for each target. It writes `interface Nve1` with `source`, the segments' `local_address`, and `vni <vni> head-end peer-list protocol bgp` for each segment, which floods to the VTEPs BGP finds. A session that carries `l2vpn-evpn` is enabled in `l2vpn-family evpn`, beside `policy vpn-target`, the switch's own, which takes only the routes whose targets a segment imports. A session for `l2vpn-evpn` alone gets `undo peer <address> enable` in the IPv4 family, which takes every IPv4 session until told not to, and no route-policy. VRP builds no loopback, so the address of the VTEP is a VLAN interface's. It refuses a VNI above 16000000, which the CE6855 refuses, `port` and `mac`, an IPv6 VTEP, a VLAN interface on a segment's VLAN, and a route reflector client or a prefix limit beside `l2vpn-evpn`. The switch refuses a new route distinguisher until the undo of the old is committed, and that undo takes the segment's targets with it, so a plan that changes one is refused with what to do. A CE6855 on V200R005 with the `CE-LIC-VXLAN` license committed a segment, its VTEP on a VLAN interface of a VLAN with no ports, and an iBGP session to a far VTEP that does not exist, with `commit trial`, and the next plan was empty. A change of targets and the removal went into a candidate, and the plan against `display configuration candidate merge` was empty. No far VTEP came up and no MAC address was learned, so it is experimental ([#351](https://github.com/takodotid/circuit/issues/351)).
- **234.** This replaces decision 145's Junos `rate_limit.output`. A QFX5100 on 21.4 takes a port's `class-of-service interfaces <port> shaping-rate`, and `commit check` and `display set` show nothing wrong, but `show class-of-service` marks it ignored on that platform, and Juniper lists port shaping on other models only. So Junos refuses `rate_limit.output` and says to limit the traffic where it comes in, or on the far device. Policing what arrives, `rate_limit.input`, stays ([#398](https://github.com/takodotid/circuit/issues/398)).
- **242.** Junos writes `routing.tables` and `routing.policy_routing` as Juniper's filter-based forwarding. A table is a `virtual-router` routing instance without interfaces, as a QFX5100 has no `forwarding` instance, and a RIB group of each family, `circuit-tables` and `circuit-tables-v6`, puts the main table's interface routes in every table, as Juniper's example of filter-based forwarding does. A filter of each family, `circuit-policy-routing` and `circuit-policy-routing-v6`, holds a term for each rule that can match the family, in order, and sits on each VLAN interface, routed port and LAG, and tunnel of the main table with an address of it. An interface a rule names takes a filter of its own, named after its unit, with the rules for every interface too. A rule to `main` accepts, so the main table routes the packet. `fallback: "main"` is a default route of the table to `inet.0` or `inet6.0`, `next-table`, so Junos refuses a table's own default route beside it, and rules to one table with other fallbacks. A BGP session's `routing_table`, an `in_interface` of a VRF, and policy routing beside `qos.marking` or a routed port's `ingress_acl` are refused. They passed `commit check` on tako-tor-01 (QFX5100, 21.4R3-S8.5) in a private candidate, set, changed, and removed, and each plan against what the candidate printed was empty. Nothing was committed, so they are experimental ([#410](https://github.com/takodotid/circuit/issues/410)).
- **243.** Where a QFX5100 passes `commit check` on a feature that Juniper's documentation or Feature Explorer doesn't give it, Junos refuses the feature, as it refuses loose uRPF: `commit check` proves the syntax, not what the switch runs. IPFIX with its timeouts passed `commit check` on tako-tor-01 (QFX5100, 21.4R3-S8.5), and Feature Explorer lists inline flow monitoring and IPFIX for no QFX5100, so Junos exports sFlow only and refuses `active_timeout` and `idle_timeout` ([#410](https://github.com/takodotid/circuit/issues/410)).
- **246.** This replaces decision 231's "VRP builds no loopback". VRP writes each of `interfaces.loopback` as `interface LoopBack0` and on, numbered in the order the config lists them, as Junos numbers its loopback units: a loopback that is renamed or moved is written again under its new number. It holds the loopback's description, VRF, addresses, and OSPF settings. A BGP session's `local_address` may be a loopback's, and so may the address of a VTEP, which stays experimental as EVPN is. A CE6855 on V200R005 committed a loopback with both families, in a VRF, in OSPF, and as a session's source, with `commit trial`, and the next plan was empty ([#413](https://github.com/takodotid/circuit/issues/413)).
- **247.** VRP writes each of `interfaces.gre` as `interface Tunnel0` and on, numbered in the order the config lists them, as decision 246 numbers loopbacks, with its description, `tunnel-protocol gre`, `source` for `local_address`, and `destination` for `remote_address`, then its addresses and OSPF settings. GRE between IPv6 addresses, and a tunnel in a VRF, are not built. A CE6855 on V200R005 committed a tunnel with both families inside it, and a static route through it, with `commit trial`, and the next plan was empty. No packet crossed it ([#413](https://github.com/takodotid/circuit/issues/413)).
- **264.** VRP writes each of `services.dhcpv6_server` as a DHCPv6 pool named after it, which its VLAN interface serves with `dhcpv6 server`, and `dhcpv6 enable`. The pool's `address prefix` is the smallest prefix that holds `pool`, a /127 at the longest, with `lease_time` as both lifetimes, and the addresses of that prefix outside `pool` are excluded: a CE6855 refused more than 1024 of them, so VRP refuses a pool that leaves more out. The switch refuses a `-` in a pool's name, and a new prefix that overlaps the pool's old one, so a changed prefix is undone first, after what it excluded. A pool goes once its VLAN interface lets go of it. V200R005 has no prefix delegation. Unlike decision 163's DHCP server, a line ties the pool to its interface, so a test on a switch proves it, though no host asked it for an address. A CE6855 on V200R005C00SPC800 committed it with `commit trial`, read it back with an empty plan, and took a change and the removal in a candidate ([#415](https://github.com/takodotid/circuit/issues/415)).
- **265.** VRP writes `monitoring.flow_export` with `protocol: "netflow-v9"` as Huawei's NetStream: `netstream export ip version 9` and its collectors, at most two, and the same for IPv6, then on each watched port `netstream inbound ip`, `netstream inbound ipv6`, and its sampler. Whether the switch keeps every packet without a sampler is not known, so `sampling` is required, 1 to 65535. The active timeout is in whole minutes, 1 to 60, and the idle one 5 to 600 seconds; the switch's own, 30 minutes and 30 seconds, are not printed. A CE6855 on V200R005C00SPC800 committed it on a spare port with `commit trial`, and the plan after was empty, but no packet crossed the port. IPFIX is not tested ([#415](https://github.com/takodotid/circuit/issues/415)).
- **266.** VRP runs each of `monitoring.probes` as an NQA test of Circuit's own administrator, `nqa test-instance circuit <name>`: `test-type icmp`, its target, source, and VRF, `frequency` for `interval`, and `start now`. The switch asks before it changes a running test, and stops it, and refuses to delete one, so a test that changes is stopped first and started again last, and one that goes is stopped, then deleted after every other step. A test's name takes no `-`, 32 characters at most. A CE6855 on V200R005C00SPC800 committed and ran them with `commit trial`, the plan after was empty, and a change and the removal went into a candidate ([#415](https://github.com/takodotid/circuit/issues/415)).

## BGP communities

- **18.** Communities: the scheme's `asn` is the network's when absent; sites are written once, in `circuit()`; `learned_at_site` tags by the site's number; every option is an object, with its own `description`, plus `custom_descriptions`; no `requests` block.
- **29.** Communities: `learned_from_group` and `do_not_announce_to_as`; a `_group` option needs `groups`, `learned_at_site` a site with a number; one `communities` block on a neighbor or neighbor group; an import honors no request unless the policy says so.
- **39.** Requests about one AS (do not announce, prepend) are offered toward upstreams, exchanges, and peers, not between customers. Customers share one export policy; a special customer gets its own.
- **50.** A customer's routes get no `learned_from_as` tag, so customers share one import policy.
- **157.** On VRP, every BGP session sends communities, `peer <address> advertise-community`, as RouterOS, Junos, and FortiOS do without a setting. The switch sends none without it, so an export policy that sets a community would set it for nothing.

## A project's files

- **3.** A project has `circuit.ts`, `sites/`, and `tenants/`. The rest is free.
- **15.** Parts are keyed by hostname. A device file writes its own `name`.
- **16.** No unclear globals in a file. Everything is written in its device first; what to share is decided after.
- **46.** A device writes its own VLANs. Circuit takes nothing from a site: in `circuit()`, a site is only its name, number, and description.
- **47.** A device takes a VLAN whole from its site file. Facts a site's devices share are named in its site file. A linked port is described `<far device> <far port>`. Defaults are not written: no `routing_table: "main"`, no `distance: 1`, no BGP `asn`.
- **60.** Tenants merge whole, `merge([terramix, elemech])`, one name per tenant.
- **61.** A tenant's secrets are written in its data, never built from its name.
- **67.** A tenant's addresses, VLAN IDs, and ports are written by hand per tenant, never derived from a number.
- **68.** A tenant's names (VLANs, interfaces, sets, DHCP server) are written by hand in its data, so a text search finds them.
- **69.** A device takes its sources with `include`, right after `name`: `include: [tenants.parts]`.

## The `circuit` command

- **27.** `circuit fmt` ships with Circuit. It is Prettier inside Circuit, styled by the project's `.editorconfig`, and not opinionated.
- **73.** Circuit installs with one shell command, which then starts a project. There is no `circuit init`: in a folder without a project, `circuit` offers to start one.
- **74.** `circuit` alone opens a menu. A command can be run straight away, such as `circuit validate`. Core: `validate`, `diff`, `apply`. Utilities: `exec`, `bgp`, `access-console`, `studio`, `rename`, `fmt`. Secrets: `secrets`. Then `update`.
- **75.** No snapshots. `diff` and `apply` read the live device. LLDP is compared with `link` while Circuit is connected.
- **76.** `apply` shows what would change and asks, no by default. `--confirm` sends without asking. `build` is gone: `apply` shows the plan.
- **79.** A git hook in `.circuit/hooks` stops a commit with a secret in plain text in a secrets file, or with a project that does not validate. A 1Password reference passes. There is no `circuit commit`: VS Code commits.
- **80.** A full install pins Circuit as a package in the project (Bun first, Node later). The `circuit` command then runs the project's own version.
- **83.** Circuit installs like an app: on Windows in `%LOCALAPPDATA%\Programs\Circuit`, on PATH and in Settings > Apps; elsewhere in `~/.local/bin`. The install command, run again, updates Circuit, and sets up a project already in the folder without questions. `circuit uninstall` removes Circuit, never a project. In a full install, the installed `circuit` runs the version the project pins (80).
- **85.** `circuit env` is `circuit secrets` (`circuit secret` still works).
- **86.** `circuit migrate` writes a 0.x project again as a v1 project, and lists what did not move.
- **96.** `.circuit/VERSION` is `.circuit/version`, lowercase as `.circuit/secrets` is.
- **97.** `circuit update` offers the last five versions newer than the current one, of its major version, newest at the top, and Stay. A version an advisory affects is never offered, and one that is affected offers no Stay (102). `--confirm` takes the newest.
- **99.** Circuit remembers the projects it ran in (`~/.circuit/projects.json`). A version kept in `~/.circuit/versions` that none of them pins any more is removed.
- **100.** The installed `circuit` is the manager. Before every command but `uninstall`, it checks npm, at most every 30 seconds, and updates itself to the newest release of its major, then runs the command as that version. Offline, it warns and goes on. A project's version never changes with it.
- **101.** Every command in a project runs the version in `.circuit/version`. One not on the machine is downloaded after a yes, or without asking in CI.
- **165.** A package, such as one for Homebrew or Arch Linux, installs the same release binary and a marker beside it, `<prefix>/share/circuit/package-manager`: the command that updates the package, then the command that removes it. With the marker, Circuit only checks for a newer version, and `circuit update --app` and `circuit uninstall` name that command and change nothing. Circuit itself names no package manager.
- **149.** `circuit nat lookup <address> [port]` answers an abuse report from the config alone, never from a device, with decision 147's mapping. A pool address and a port give the subscriber. A subscriber gives its pool address and ports. A pool address alone lists every subscriber that shares it (64 at most in text), for a report that has no port. It answers for a past day only from the config of that day, so a person checks out its commit first. A port below 1024 or past the last block, and an address in no pool, are said so and exit 1. It skips a rule `validate` refuses. It does not log translations ([#227](https://github.com/takodotid/circuit/issues/227)).
- **150.** `circuit addresses` counts a source NAT's `to_pool` and its subscribers' `if.src`, and a PPPoE server's `pool` and `local_address`, as address space in use, each labeled with its device. A pool that is no prefix is a range, placed in a space by the smallest prefix that holds it. A range is an address taken inside a segment only when both ends are in that segment, and a block otherwise. A rule without a pool, such as masquerade, uses none. A DHCP pool outside every segment is still not listed ([#226](https://github.com/takodotid/circuit/issues/226)).
- **106.** Utilities also has `communities` (`--format nlnog`, `alice`, or `json`) and `addresses`, and `sync` comes as #170 proposes. No `refresh`: `diff` and `apply` fetch a registry's prefix sets each time and plan them like any list. `wireguard` and `graph` are dropped.
- **114.** `--experimental` lets through a feature built from public documentation but not tested on a real device yet. It stays until Circuit can test on emulated devices (containerlab, [#178](https://github.com/takodotid/circuit/issues/178)).
- **232.** Circuit checks the SSH host key of each device, and of a console's jump host, as OpenSSH's `StrictHostKeyChecking accept-new` does. That is the industry standard, and Ansible checks `known_hosts` by default too. It reads `~/.ssh/known_hosts` and `/etc/ssh/ssh_known_hosts`: plain and hashed names, `[host]:port`, `*`, `?`, `!`, and `@revoked`, but not `@cert-authority`. A host not known is let in, and its key is added to `~/.ssh/known_hosts` with a line that says so. A key that matches none known for the host is refused before any password or key is sent, with the file, the line, both fingerprints, and the `ssh-keygen -R` command. Circuit offers a known host only its known key types, within those its platform takes, where OpenSSH only prefers them. None in common is refused. There is no setting or flag for it.

## Secrets

- **92.** Secrets are Circuit's own, without dotenvx: a network's secrets file holds `NAME="value"` lines, names readable, each value AES-256-GCM with a key made from one password by scrypt and the name bound to it. It is committed. Only one password, no key pair.
- **93.** The secrets file is `.circuit/secrets`, or the file `circuit({ secrets: { file } })` names, such as a lab network's with its own password. The password is never in `circuit.ts`.
- **94.** The password comes from `CIRCUIT_SECRETS_PASSWORD` in the environment, from `CIRCUIT_SECRETS_PASSWORD="op://..."` in the secrets file, or is typed when Circuit asks. The first `circuit secrets` asks to choose one. If it is left empty, Circuit makes one and shows it once.
- **95.** `circuit secrets` alone, in a terminal, opens every secret decrypted in a text editor that is part of Circuit, nano-like: Ctrl+S saves encrypted, Esc or Ctrl+X leaves. A value that didn't change keeps its encryption. Values are never written to disk in plain text.
- **105.** Circuit remembers secrets only after a yes: for 10 minutes, 30 minutes, or 24 hours, never longer, in the memory of a small Circuit process, never in a file. It answers only a program with its token. The question warns that any program run by the person can get them, and locking 1Password doesn't lock them. `circuit secrets forget` drops them.
- **128.** Everything Circuit prints, and every answer Studio gives, shows each secret of 6 characters or more as `<redacted>`, including what a device quotes back. A shorter one would hide ordinary words and numbers too. The interactive `access-console` passes the device through as it is ([#259](https://github.com/takodotid/circuit/issues/259)).

## Studio

- **81.** Studio is a Vue 3 app built by Vite and carried in the binary; its graph is drawn with Cytoscape. Without snapshots (75), a device's page reads the device only when asked, "Read from the device now", as `circuit diff` does, and keeps nothing.
- **82.** Studio's Secrets page shows how each value of each secrets file is kept. To see the values, a person types the file's password; the browser decrypts them, and the password is never sent or kept. A value in plain text never leaves the server. Studio reads a device only when the password comes from 1Password or the environment, and never on a server.
- **115.** Studio's pages have plain paths, such as `/secrets`, not `#secrets`.

## Releases

- **84.** Versions come from npm dist-tags: `latest` is stable, `rc` a release candidate, `latest-<major>.<minor>` a backport (103). A stable release rebuilds the site; a candidate or a backport doesn't. An update stays within its major version.
- **102.** A version with a security problem is marked by a GitHub security advisory on the repository, any severity, read at most every 2 minutes. A project on an affected version runs nothing until it moves to a fixed one; the fix closest to its version is always offered.
- **103.** A backport, a stable version older than npm's `latest` of its major, goes under the dist-tag `latest-<major>.<minor>`, as npm's own `latest-6`, is not marked Latest on GitHub, and doesn't rebuild the site.
- **104.** Each release's `SHA256SUMS` is signed with an Ed25519 release key, the secret `RELEASE_SIGNING_KEY`. Circuit installs a binary only with a signature by a key it carries. The install commands check `SHA256SUMS.sshsig` with `ssh-keygen`.

## This repo

- **91.** Prettier formats Circuit's own repo (`prettier.config.mjs`). `circuit fmt` formats a project, styled by its `.editorconfig`.
- **107.** Agent instructions live in `AGENTS.md`, the agents.md standard. There is no `CLAUDE.md`. A folder with rules of its own has its own `AGENTS.md`, such as `src/platforms/` and `docs/`.

- **109.** Commit messages use the imperative mood: `fix(cli): keep remembered secrets for 24 hours`.
- **110.** The docs have five parts: Get started, Write a project, Run it, Integrations, and Reference. The Academy stays apart.
- **113.** What Circuit supports is the feature matrix in the docs. A gap Circuit plans to fill is a GitHub issue, with what each vendor offers. There is no separate coverage file.
- **118.** The decisions are `DECISIONS.md` at the root of the repo, not on the docs site. There is no `design/` folder.
